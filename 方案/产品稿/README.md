# 产品稿（人读导出件）

> 本目录只放**导出件**：给用户/团队快速看懂"要做什么"，不承载事实源。
> 真源：`project-state/契约/产品需求文档.md`（PRD 正本）。二者冲突时**以 PRD 正本为准**。

## 导出件必须带的两个标注

每一份 `.md` 首部（导出时自动写入，别手改）：

```
导出日期：YYYY-MM-DD
源路径：project-state/契约/产品需求文档.md
```

`solution_audit.py` 会逐份检查这两个标注；缺任一 → ERROR。

## 常见导出件

| 文件 | 内容 | 何时出 |
|---|---|---|
| `PRD摘要.md` | 目标用户、核心场景、功能范围、不做清单 | 【关卡①】前，产品经理 |
| `功能清单.md` | 功能模块 → 优先级 → 验收要点（一行一项） | 【关卡①】前 |
| `流程说明.md` | 主流程/异常流程（可配 Mermaid，纯文本可读） | 关卡①前或按需 |
| `范围与假设.md` | 本轮范围边界、未确认假设、待客户拍板项 | 每轮范围变更时 |

## 纪律

- **不在导出件上改内容**：要改就改 PRD 正本，然后重新导出覆盖。
- 导出件命名不带日期（日期在标注里），避免同一份东西堆出十几个版本。
- 一份导出件对应一张需求卡时，在卡里写明导出件文件名，便于追溯。
