# 方案视图区（方案/）

> **定位**：本项目面向人的「方案视图」。客户给的原始方案文件、可以拿给人看的产品稿、原型图，都在这三个目录里一眼可查。
> **不是第二事实源**：真源仍在 `project-state/契约/`；本目录是**导出视图 + 原始件归档**，导出件可随时按真源重新生成并覆盖。
> **维护人**：项目经理（建目录、维护本文件与 `原始资料/清单.md`、关卡前刷新、批次/里程碑收口跑 `solution_audit.py`）。
> **最后刷新**：<日期> ／ <刷新人>（每次导出或收口后更新这一行）

## 三个子目录

| 目录 | 放什么 | 谁写入 | 真源 / 上游 |
|---|---|---|---|
| `原始资料/` | 客户给来的方案、参考文件、会议材料、竞品资料等**原始件**（不改内容，只归档） | 项目经理登记 `清单.md` 后归档 | 无（原始件本身就是唯一实体，**不要**另存副本到别处） |
| `产品稿/` | 产品经理产出的**人读导出件**：PRD 摘要、功能清单、流程说明等 | 产品经理导出 | `project-state/契约/产品需求文档.md` |
| `原型图/` | 低保真原型截图、高保真页面图（按屏/档位） | UI设计师导出 | `project-state/契约/UI资源/prototypes/prototype.spec.json`、`契约/UI资源/designs/<页面>.html` |

## 铁律（四条）

1. **真源不改道**：`产品稿/`、`原型图/` 里的每一份文件都是**导出件**，必须在文件头/首行标注 `导出日期：YYYY-MM-DD` 与 `源路径：<相对项目根的路径>`；真源改了就重新导出覆盖，**不要在导出件上直接改内容**。
2. **原始资料只进不改**：客户原件放进 `原始资料/` 后保持原样；消化结论写到 `project-state/`（需求卡/契约/思路），**不要**在原件上批注。
3. **对外交付不从这里发**：要发客户的正式件仍走 `交付/` + `发出记录.md`（交付 vs 产物判定见 `agent.md` 2.2）；本目录仅供内部与用户随时查看。
4. **根下只放索引**：`方案/` 根下只允许本 `README.md`；其余都进三个子目录（避免又出一层"随手放"）。

## 什么时候刷新

| 时点 | 动作 |
|---|---|
| 完整模式初始化（建 `方案/` 时） | 建三子目录 + 本文件 + `原始资料/清单.md` 表头 |
| 【关卡①】产品需求确认前 | 产品经理导出 `产品稿/`（或在卡里写明"本卡无用户可见产品稿"） |
| 【关卡③/④】设计方向与高保真定案前 | UI设计师导出 `原型图/` 四档图 + 更新 `原型图/清单.md` |
| 每批收口 / 里程碑收口 | 按需补充导出件，更新本文件顶部「最后刷新」 |
| 收口体检 | `python -X utf8 scripts/solution_audit.py <项目根>`（0 干净 / 1 有 ERROR / 2 无法检查——**2 不是没问题**） |
