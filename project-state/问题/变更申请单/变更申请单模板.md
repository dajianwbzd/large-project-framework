# 变更申请单（模板 · 三类合一：代码 / 配置 / 数据）

> 依据：`契约/生产运维.md` §2（变更分级与审批）。**生产的一切变更都必须先有单子**——数据库变更沿用 v3.8 的 SQL 修改申请单语义，本模板把"代码变更"与"配置变更"一并纳入同一套单证。
> 使用方式：复制本文件 → 命名为 `CR-<YYYYMMDD>-<NNN>-<类型>.md`（类型 ∈ `常规代码` / `紧急代码` / `数据配置`）→ 存 `问题/变更申请单/` → 填完提交审批 → 执行后回填留痕。**模板本体不要直接改**。

## 0 三种类型怎么选

| 类型 | 何时用 | 审批 | 观察窗口 | 事后要求 |
|---|---|---|---|---|
| `常规代码` | 计划内的功能/依赖/模板发布 | 主控 | ≥10 分钟（按 §0.6 SLO 判据） | 走完整发布流程（`生产运维.md` §3） |
| `紧急代码`（hotfix） | 生产 P0/P1，先修后补单 | 主控 + **用户知会** | 实时盯到指标恢复 | **24 小时内补齐本单 + 事故报告** |
| `数据配置` | 改 SQL/加列/改口径/改配置/轮换密钥 | 主控 + **安全审计（风险评审）** | 按影响面：只读核验 ≥10 分钟，写数据 ≥1 个业务周期 | 迁移登记 `契约/数据模型.md` + 变更日志 |

> 口径（v3.22.0）：**运维发起 → 主控放行 + 安全审计做数据/配置风险评审 → 项目经理登记与知会**。`sql` 类单号须回填到 `契约/数据模型.md` 的迁移登记表「申请单编号」列。

## 1 必填字段（缺任一项 = 不予批准）

| 字段 | 要求 | 不合格示例 |
|---|---|---|
| 单号 / 类型 / 级别 | `CR-日期-序号-类型`；级别 P0~P3（紧急）或"常规" | 无级别 |
| 发起人 / 时间 | 角色 + HH:MM（含时区） | "昨天" |
| **变更内容** | 文件清单 + **每文件 sha256**；SQL 给**完整可执行语句**；配置给键名（**不给密钥值**） | "改了下管理台" |
| **影响面** | 受影响功能 / 数据表 / 用户范围 / 是否**不可逆** | "影响不大" |
| **回滚方案** | 回滚动作（具体命令）+ 回滚判据 + 预估耗时 | "出问题再说" = 无效 |
| **备份证据** | 备份文件路径 + 校验结果（如 `integrity_check=ok`） | "应该有人备份过" |
| **观察窗口与判据** | 看什么、什么值算成功、什么值要回滚 | "观察一下" |
| 审批栏 | 主控署名 + 时间；（数据/配置类）安全审计署名 + 时间；紧急类用户知会时间 | 空栏 |
| 执行留痕栏 | 实际时间线（HH:MM 动作 → 输出摘要）+ 最终结论 + 偏差 | 只写"完成" |

## 2 红线（命中即停手并上报，见 `生产运维.md` §2.2）

1. 无备份改数据 2. 生产手改代码不走流程 3. 在生产跑 seed/压测/删数据
4. 无回滚方案发布 5. 一次发布夹带多个不相关变更 6. 事故中同时做多个方向的动作
7. 跳过观察窗口宣布成功 8. 把密钥/口令/真实用户数据写进本单
9. 对 prod 执行迁移 down 脚本（**数据只前滚不后退**）10. 无人知会地重启/停机

## 4 校验清单（提交前逐条打勾 + 可机器核验）

- [ ] 单号命名合规：`CR-<YYYYMMDD>-<NNN>-<类型>.md` 落在 `问题/变更申请单/`
- [ ] 每个改动文件都有 sha256（`sha256sum <文件>` 的输出直接贴，不手抄）
- [ ] 回滚命令**是可直接执行的**（不是"还原到之前状态"这类描述）
- [ ] 备份文件确实存在：`ls -l <备份路径>` 有输出且大小 > 0
- [ ] 数据类：迁移已在 `契约/数据模型.md` 登记；含"数据是否已前滚"判定
- [ ] 观察窗口含**版本指纹**一行（防止"部署了旧包还宣布成功"，真实案例见 `生产运维.md` 附录 A）
- [ ] 审批栏已签（数据/配置类缺安全审计签名 = 未批准）
- [ ] **本单不含任何密钥值、口令、真实用户数据**

## 5 反例（真实教训，别重犯）

| 反例 | 后果 | 正确做法 |
|---|---|---|
| "先改了再补备份" | 无法回到改前状态，事故只能硬扛 | 备份 → 校验 → 再动 |
| "回滚就是切软链，数据不用管" | 数据已前滚时切回旧代码 → 新结构读不了，二次事故 | 先判 Q1（数据是否已前滚），命中即**禁止回滚代码** |
| "健康检查 200，发布成功" | 前端/功能级坏不会被健康端点抓到（实测：坏版本仍 `ok:true`） | 观察窗口必须含**坏掉那个功能的断言**与**资产指纹** |
| "版本号是 0.1.0，跟上次一样" | 版本号多年不变，无法定位构建 | 登记**资产 sha256**，不靠版本号 |
| "备份就 `cp` 一下库文件" | SQLite 开 WAL 时主库可能只有几 KB（实测 4096B vs WAL 127KB）→ 备了个空壳 | `VACUUM INTO` 或停服整体打包 `data/` |
| "紧急修复顺手把命名也改了" | 一次改多处，回滚无法归因 | 最小改动面（≤3 文件/≤30 行），单主题 |
