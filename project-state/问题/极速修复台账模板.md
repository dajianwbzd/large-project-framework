# 极速修复台账模板

> 主控维护 ｜ **一项目一份** ｜ 落点：`project-state/问题/极速修复台账.md`（**极速修复模式的唯一留痕落点**）
> **为什么要它**：极速修复（`turbo-repair`）**不建卡、不派子代理、只跑冒烟/定向**——省下来的正是框架平时用来记账的那些动作。
> 于是**"快"与"漏"在纸面上长得一模一样**：不记台账，事后没人能说出改过什么、为什么退、哪些面没测。
> **它记的是"这一轮省了什么、代价是什么"，不是"这一轮干得多快"。**
> **v5.12.1 补两列**：`basis`（这一轮**依据**哪张需求卡 / 测试卡 / 用例库——空 = ERROR）与 `pack`（这一轮要交给客户的**体验包**路径）。
> 极速省的是**派子代理与建新卡**，**不是省"排查依据"**，也**不是省"给客户看的东西"**（详见 §1 第 2、3 条）。
> 机器只读下面的 `<!-- machine:turbo -->` 围栏块；检查器：`python scripts/framework_lint.py <项目根>` 的 **K 组**
> ——**没有本文件 = 本项目没用过极速修复，记 INFO 跳过（不是 ERROR，也不是"无法检查"）**。

## 1. 五条纪律（先读这一段）

- **入口在用户手里**：只有用户点名（`极速` / `极速修复` / `极速修复模式` / `快速解决`，或明确说「别建卡、别派子代理」）才能进。
  **主控与任何角色都不许**以「这个改动看起来很小」为由自行进入（方法级判据 **R17**：快档的入口必须在被服务的人手里）。
  **跑批 / 无人值守轮次里不得进入**——入口是用户点名，无人可点。
- **一行一轮，开与退都记**：`exit` 与 `exit_reason` **成对**（**两个都空 = 仍在极速中**，合法；一空一满 = 进了没记退 / 退了没记因，检查器报 ERROR）。
- **先按依据排查，再动手（v5.12.1）**：用户反馈只是**线索**——读反馈原文（现象 / 复现 / 影响面）后，**回到既有资产定位失败面**：
  对应的**需求卡** `需求卡/card-NNN/`（`anchor` 改哪里 / `entry` 怎么复现 / AC）、**系统级测试卡** `测试卡/tc-NNN/`（覆盖矩阵、发现项 7 列锚点）、
  **用例库** `代码/测试/用例库.md` 的 `CAS-NNN`、相关契约（冷启动先跑 `python scripts/recall.py <项目根>`）。依据写进 **`basis`** 列：
  `card-013` ｜ `tc-002` ｜ `CAS-003` ｜ `card-013+tc-002` ｜ `no-card`（**确无对应卡的新小变更才写 `no-card`**，靠 X1 / X2 兜底；**v5.28.0 起 `CAS-NNN` 是合法段**——修复后**必须**把哨兵用例号追加进 `basis`，`verified=是` 而无哨兵会被 `regression_audit.py` 报 ERROR）。**`basis` 空 = ERROR**——
  **极速省的是派子代理与建新卡，不是省依据；没依据就动手不是极速修复，是"乱改"**。
- **交付面也要记（v5.12.1）**：本模式的典型用途正是**给客户快速体验 + 小功能变更**——产物要交给客户看/用时，
  **`pack`** 列写体验包（或交付物）的**项目根相对路径**；体验包里至少写明「**这一轮改了什么 / 客户怎么验 / 哪些面只做了冒烟、未独立验证**」。
  **`pack` 空 = ERROR**（本轮不涉及交付面就写 `-`）。**正式交付包（`delivery_use=deliverable`）、承诺可用与上线前一轮仍一律出局**（X6 不变）——
  体验包与正式交付包的区别是**承诺**：体验包可以说"看效果"，正式交付包不行。
- **极速轮次的自检不构成验收**：实现与自检是同一双手（创建者 = 验证者被打破）——`verified` 必须显式写 `否`，
  **不许置卡 `done`、不许宣称"已验收"、不许拿极速证据进 ⑥ 验收前置检查**。要 GO，回正常流程按档补跑。

## 3. 机读块（必须有）

```text
<!-- machine:turbo -->
id | at | source | basis | symptom | files | depth | evidence | pack | exit | exit_reason | verified
TRB-001 | 2026-09-30 15:41 | 用户原话：「极速修复这几个小 bug」 | card-013 | 客户列表页筛选项点第二次不生效 | 2 | smoke | 证据/极速修复/TRB-001.md | 交付/体验包/20260930-1541 | 2026-09-30 15:52 | 用户确认效果 OK，本轮收口 | 否
TRB-002 | 2026-09-30 16:20 | 用户原话：「快速解决一下这个文案」 | tc-002 | 首页按钮文案与客户口径不一致 | 1 | targeted | 证据/极速修复/TRB-002.md | - |  |  | 否
<!-- /machine:turbo -->
```

列义（**12 列，顺序固定**；v5.12.1 在 `source` 后插入 `basis`、在 `evidence` 后插入 `pack`）：

- `id` = `TRB-NNN`（**全局唯一、只增不减、永不复用**；格式 `TRB-` + 3 位数字；按出现顺序升序）
- `at` = 进入时间 `YYYY-MM-DD HH:MM`
- `source` = **谁点名的**（用户原话要点，**不许空**）——这一列是"入口正当"的唯一纸面凭据
- `basis` = **这一轮依据什么排查的**（`card-NNN` ｜ `tc-NNN` ｜ `CAS-NNN` ｜ 以上用 `+` 组合 ｜ `no-card`；**不许空** = ERROR，形状不符 = WARN）——极速修复不建新卡，但**必须读既有卡/测试卡/用例库**；`no-card` 只留给确无对应卡的新小变更；**v5.28.0：`verified=是` 的行 `basis` 必须含 `CAS-NNN` 哨兵**（修过的问题必须留防复发用例——`regression_audit.py` 线 4）
- `symptom` = 现象一句话（**同一现象反复出现时写法要一致**，检查器按它数"同一个问题几轮了"）
- `files` = 本轮改动文件数（正整数）——**≥4 就是退出线 X1**
- `depth` = `smoke`（冒烟）｜`targeted`（定向）——**极速轮次只有这两个档**；写 `full` 说明这一轮本不该走极速（检查器报 ERROR）
- `evidence` = 证据指针（相对项目根的路径：命令与结果、截图、日志），**不许空**
- `pack` = **要交给客户的体验包（或交付物）的项目根相对路径**（**不许空** = ERROR；本轮不涉及交付面写 `-`；写了路径但文件不存在 = WARN）——本模式的典型用途就是**给客户快速体验 + 小功能变更**，交付面也要有账
- `exit` = 退出时间（**仍在极速中留空**）
- `exit_reason` = 退出原因（**仍在极速中留空**）；正常收口、或命中任一退出线都要写清是哪一条
- `verified` = `是` ｜ `否`（**是否经过独立验证**；极速下常态是 `否`——**必须显式写**，不写等于把"没独立验证"读成"验证过了"）
- **字段内不许出现 `|`**（列分隔符）；要写多个用 `,` 或 `/`

## 4. 强制退出线（命中任一：当场退出极速、写 `exit` + `exit_reason`、回正常流程）

| # | 退出线 | 为什么 |
|---|---|---|
| X1 | 一次修复**动到 ≥4 个文件** | 越过"小改"的经验边界 |
| X2 | **触及契约 / 接口 / 数据模型 / 权限 / 敏感数据 / 生产变更 / 迁移** | 不可逆面必须有卡、有确认、有独立验证 |
| X3 | **同一个问题连续 3 轮还没好** | 不是小 bug，是没找到根因 |
| X4 | **冒烟/定向测试发现面超出预期**（牵出别的模块） | 影响面已不是"改动面"，档位判断失效 |
| X5 | **用户改口**（"认真做 / 走正常流程 / 别用极速了"） | 入口权在用户，退出权也在用户 |
| X6 | **正式交付包、对外件、上线前一轮** | 这两类轮次必须 `test_depth=full`（见验收标准 #53）——极速修复不得用于它们。**注意（v5.12.1）**：给客户**快速体验/看效果**的**体验包不在此列**（它正是本模式的目标场景），但必须写进 `pack` 列、并写明"哪些面只做了冒烟、未独立验证" |

**退出后怎么接**：**已改的代码不推倒**——补建卡与证据，按项目档位把该跑的那一轮测试补上；
**极速里省下的测试不得当成"已经测过"**（本模式最容易出的假保护）。

## 5. 与其它文件的分工（别互相替代）

- `问题/极速修复台账.md`（本文件）：**极速轮次的进入、裁剪、退出**（跨轮累积）
- `问题/变更申请单/`：**落地要动契约/结构**时走这里——命中它就意味着**已经越过退出线 X2**，别在极速里改
- `需求卡/card-NNN/`：退出极速后**补建**的卡（正常流程的驱动单位）
- `测试卡/tc-NNN/`：退出极速后按档补跑的测试；极速轮次**不建测试卡**，档位记在本台账 `depth`
- `记忆/指导发现台账.md`：极速暴露出的**框架级绕过**（比如"执行者自己判它是小改"）登记在那里，别混进本台账

## 6. 诚实边界

- 检查器（K 组）只核**台账自己写的东西自不自洽**，**核不出**：这一轮到底派没派子代理、有没有真的只跑冒烟、
  `files` 是不是真只改了那么几个文件、`evidence` 指向的证据是否真实、**`basis` 写的那张卡是不是真对应本次现象**、
  **`pack` 里的体验包内容是不是真能给客户看**（`pack` 只核"写了路径 / 路径存在"，核不了包里的东西够不够）。
- **没有台账 ≠ 没问题**？——不。**没有台账 = 本项目没用过极速修复**（INFO 跳过，不报错）；
  但**有台账却没写机读块 / 写得不自洽 = ERROR**：那是"用过却没留下可核的账"。
- `source` 只能核"写了谁点名的原话要点"，**核不出当时用户是否真的说过**；`verified=否` 的轮次**一律不得据以验收**。
- 参数（4 文件 / 3 轮 / 冒烟范围）来自 2026-09-30 用户描述与真实小改的经验边界，**换项目、换宿主要重新标定**。
