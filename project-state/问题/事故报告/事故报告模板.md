# 事故报告（模板 · 含演练记录）

> 依据：`契约/生产运维.md` §5（事后复盘与沉淀）／§6（演练门禁）。**P0/P1 必写，P2 可简写；回滚/备份演练用同一模板**（文件名 `演练-<日期>.md`）。
> 使用方式：复制 → 命名 `incident-<YYYYMMDD>-<NN>.md`（演练为 `演练-<YYYYMMDD>.md`）→ 存 `问题/事故报告/`。**模板本体不要直接改**。

## 0 写报告的三条纪律

1. **先写时间线，再写结论**——时间线是事实，结论是判断；事实与判断混写 = 复盘变成自我辩护。
2. **必须回答"为什么没被拦住"**——只答"谁操作错了"不是根因（人错了要问机制为什么允许他错）。
3. **改进项必须带 owner + 期限 + 验证方式**——没有这三样的改进项是口号。

## 2 演练记录（用同一模板，填这几项即可）

```markdown
# 演练记录 演练-<YYYYMMDD>：<回滚 / 备份恢复 / 切流>

- 依据：`契约/生产运维.md` §6（上线门禁要求）
- 时点：<首次上线前 / 拓扑变更后 / 周期抽查>
- 演练类型：回滚演练 / 备份恢复演练 / 切流演练
- 环境：<隔离副本目录 / 副本库 / tmp 路径>（**禁止在生产做**）
- 造的"坏"是什么：<具体改了哪个文件/哪条数据，能被什么判据抓到>
- 时间线：见 §B 表（含启动、切换、复验、回滚）
- 判据结果：健康端点 <…> ／ 坏掉的功能 <已恢复> ／ 资产指纹 <回到旧值>
- **RTO 实测：<N> 秒/分钟**（对照 §0.6 目标）
- 结论：通过 / 失败（失败项：<…>，修复后重演日期 <…>）
- 结论纪律：**演练失败 = 不允许上线**（不是记个待办先上）
- 清理：演练产生的副本/临时库已归位或删除（留在生产目录 = 路径纪律违规）
```

## 3 校验清单（可机器核验）

```bash
D=project-state/问题/事故报告
ls $D/incident-*.md                          # P0/P1 事故应有对应报告
ls $D/演练-*.md                              # 首次上线前应 ≥1（上线门禁）
grep -c '<[^>]*>' $D/<新报告>.md             # 0（占位符已填）
grep -qE 'RTO 实测' $D/演练-*.md && echo "演练含 RTO 实测"
grep -cE '^\| [0-9]+ \|' $D/<报告>.md        # 改进项 ≥1（带 owner/期限/验证方式）
```

## 4 反例（复盘长这样 = 白复盘）

| 反例 | 为什么不行 | 正确做法 |
|---|---|---|
| "原因是操作失误" | 人总会失误，机制为什么允许失误才是根因 | 答到"为什么没被拦住"（D2 三层问） |
| "已加强注意、下次小心" | 不可验证的改进项 | 落成检查点/规则/自动化，带验证方式 |
| "时间线凭记忆补" | 记忆会美化，复盘失真 | 用命令输出与日志时间戳（`journalctl --since`） |
| 只写技术原因，不写"为什么 40 分钟才发现" | 发现延迟往往比故障本身更贵 | 监控/告警维度单列改进项 |
| 事故报告写完就归档，规则库不动 | 同一个坑会踩第二次 | §H 规则沉淀指针必须 ≥1 项且有落盘 |
| 对客户说明里回避数据影响 | 隐瞒比事故本身更贵（商务风险） | §I 口径必须写清数据影响与补偿 |
| 演练只切指针、不造"坏" | 演练通过而真实事故照样抓瞎（实测教训） | 演练必须造一个能被判据抓到的坏 |
