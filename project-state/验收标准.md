## 验收标准

1. 共享工作区结构完整且被正确使用（需求卡/契约/tasks/代码/问题/记忆/进度/完成定义.md）
2. 需求卡机制完整运转：卡片状态流转（todo→done）、追溯链（REQ→card→task→test）闭合、经验沉淀双向同步 记忆/
3. CR 机制至少经历一次完整生命周期（发起→评审→接受/拒绝→记录）
4. api.yaml 至少经过前后端一次审查与修订
5. 任务清单.md 每项任务引用卡片与 REQ 编号，[x] 标记与验证结果一致，无跳卡；任务切片硬指标（≤5 文件/≤L）被执行
6. 记忆/决策日志.md 记录所有关键决策及理由（ADR 风格），条目标注加载优先级
7. 完成定义.md 被测试/集成/安全在验收时对照执行，验收结论以 GO/NO-GO 合并输出
8. 快速模式：**需求卡照建**（`需求卡/card-NNN/`，卡卷宗结构完整、卡状态与验收留痕在位——**队伍小不是不建卡的理由**；有开工痕迹却无卡在 `guide_audit.py` 里是 G01 ERROR，**不因 `mode=quick` 降级**）、需求卡直接驱动产出可运行版本并接受多轮迭代反馈；**裁掉的只有角色数 / 文档深度 / 测试密度三样**（裁剪面与不可裁清单见 agent.md「运行模式 → 快速模式裁剪面」，v5.4.0）；**未启用角色的工作按「临时兼岗」（运行模式要点 10）承接**——有登记（工作/原属角色/承接者/判据来源）、无"假扮已验证"痕迹、命中"必须升级"条件已转正启用该角色或切完整模式
9. 端到端产出：可部署代码 + 配置
10. 源头驱动执行：框架特定技术决策注明官方文档来源（URL+锚点），找不到文档标"未验证"

40. **长时任务估算与编排边界运转（v4.5.0；v4.6.0 加三点估算与裁尾，项目经理常设职责）**：用户按时间窗提要求或主控要长时编排时，项目经理**先出估算**（`skills/项目经理/SKILL.md` §12 + `scripts/task_estimate.py`）——每项带 **三点估算 O/M/P → 期望±σ + 估 token 区间 + 估轮次 + 依据 + 置信度**（同类实测中位数优先，n≥3；否则结构特征基线并标中/低置信度，**无依据的"大概一天"视为未估算**）；估算表落 `主控工作计划.md` 的「长时任务估算」段；**最终编排在 agent.md 主控**（项目经理只给候选序，不排产、不决定先后——越界即失守"不做元编排"的总边界）。**命中概率与裁尾（v4.6.0）**：序列报 **P(窗口内跑完) = Φ((窗口−ΣE)/σ合计)**，**P 低于下限（默认 80%）必须裁尾**（逐张移除至达标或只剩一张，被裁项进排除表写明原因）——**宁可少排也不虚报**；σ 用 BetaPERT **精确方差**（教科书 (P−O)/6 低估方差 13%，会把跑不完报成跑得完）；**独立假设与"P 是乐观口径"必须随 P 一起写明**；**估时只用于窗口选卡与预算熔断，不得作为对外交付日期承诺**；低置信度且无参考类锚的卡标 `needs_review`，编排前须人工复核或补 `参考类`。**无人值守（长时窗/夜间）四查**：① `待办/自然人.md` 未闭环项已清（依赖它们的卡不得进序列）② **不含不可逆/对外动作**（发出、删已发出副本、上线放行、push、破坏性迁移）③ **有 token 预算上限**（触顶停安全点，不静默烧完）④ 异常（P0/P1 事故、连续失败 ≥2、需改契约/扩范围）**停在安全点并留痕**而非硬扛。**替用户做的假设必须逐条留痕**（无人值守时排了哪些、裁了哪些、用了哪套区间端点）。**精度可复核**：卡收口时实测值回填 `进度/估算实测.csv`，偏差可算——**无回填的估算视为一次性猜测，不得作为长时编排依据**。`python scripts/tests/test_task_estimate.py` 全绿（估算安全承诺的回归测试，含 PERT 蒙特卡洛对拍）。

41. **成本敏感与容量熔断运转（v4.6.0，项目经理给阈值与账本 / 主控执行熔断）**：**成本敏感是项目经理的本职维度，三个维度都要有数**——**人员投入（角色数 × 派发轮次）/ 时间投入（O/M/P 与命中概率）/ token 投入（按轮次估、按流水核）**；只报时间的估算是残缺的。**编排前过可实施性关卡**：`python scripts/task_estimate.py --readiness <候选.json> [--unattended]` 出 **PASS/CONCERNS/FAIL**，判据问题只有一个「**一个开发在没人可问的情况下，能不能把这些卡做完？**」——**FAIL（退出码 1）不得进长时编排**，按关卡给出的**指名修复者**退回补齐后重跑（**不指名的发现等于没发现**）；**每条发现都有修复者**；**`undeclared`（字段没写）记"没人查过"，既不等于已就绪也不等于 FAIL**——报告里不许与"查过且干净"混为一谈。**事中账本与熔断**：`进度/成本流水.csv` 由**每轮 `--spend`** 追加（卡/角色/模型/轮次/两向 token/累计），`--burn-status` 给累计/剩余/**按角色与按模型分桶**（谁的轮次在烧钱）；**累计值每次由各行重算**（不信任存档累计列——避免第二份事实源）；成本列读 `project-state/config.json` 的 `cost_table`，**无表则留空，不猜价**。**熔断执行权在 agent.md 主控**（在 ⑥ 世界线的每轮循环里，见该节）：触顶即**停在安全点**（当前卡收口、落盘、记 `运行日志.md`、留痕报备），**不静默烧完、不"再跑一轮看看"**——**光有账本没有循环里的检查等于没有熔断**（MetaGPT `CostManager` 计量 + `Team._check_balance` 每轮熔断的定案）。**超支必归因**：估算偏低（台账问题）/ 轮次失控（流程问题）/ 范围漂移（需求问题）——三种原因三种改法。**三条通用铁律**：①**脚本失败不许静默兜底**（报错原文摆出来 + 说明确定性路径失败 + 人工判断标注"此处为人工判断"）②报告里**区分「查过且干净」与「从未查过」**③**没人确认 ≠ 默默通过**（到点无人回的事项记「未获确认」，不得写成"通过"）。`python scripts/tests/test_task_estimate.py` 全绿（关卡三档 + 裁尾 + 熔断 + 累计重算 + GBK 各自有会变红的断言）。

42. **复盘与角色职责校准运转（v4.7.0，项目经理汇总事实 / 主控与用户做判断）**：用户 2026-09 提的「**随着项目开发优化整个项目组的流程、校准各角色职责**」，明确**不是每次调用都做**——**触发按迭代，不按墙钟时间**：`python scripts/retro_calibrate.py --due <项目根>` 比的是**自上次复盘又收口了多少张卡**（`config.json` 的 `retro_cadence.every_n_cards`，默认 20），`stale_days`（默认 30）**只出陈旧提醒、不构成触发器**；读不到该项时按默认 20/30 正常工作。**为什么按迭代**：框架已有 `test_card_cadence` 这套迭代节奏词汇，**不引入第二套含义重叠的节拍器**（两套迟早打架）；且 agent 框架里**墙钟时间不映射工作量**——闲置两周会触发一次零新数据的复盘，三天干完 40 张卡又会错过漂移窗口（复盘的意义正是趁偏差还小的时候纠）。**汇总事实（`--assemble`）**：按角色出估时偏差中位数（读 `进度/估算实测.csv`，与 #40 同一份，不重复统计）与成本分桶（读 `进度/成本流水.csv`，**成本按累计列逐行差分还原**，不可得则退回 `cost_table`，**都没有就留空不猜价**）；**来源缺失时输出「未查过」，不许渲染成「没有异常」**（"这个角色成本是 0"与"我没查到"是两件事）。**机制 K：上一轮行动项必须核落地（`--actions`）**——建项时必写 `--核验证据`（`路径` 或 `路径::关键字`），核验后落**两列正交**：`落地情况`（`landed`/`evidence-missing`/`unverified`/`dropped`，**只看证据**；**证据列为空 ⇒ `unverified`，「没写证据」≠「已落地」**）与 `逾期`（`状态=open` 且 `核验轮次 ≤ 当前轮次`，**只看时点、与证据无关**）。**两列不许合并**——合并会让「**真落地了但到点没人在核收**」记成 `landed` 静默通过，正是 v4.6.0 铁律③要拦的；故它自成一类（`landed`+`逾期=是`）并被单列成「已落地但逾期未收口」小节。**退出码 1 ⟺ `unverified`/`evidence-missing`/`逾期=是` 三者任一**，不得"跳过继续"。`--close` 写 `复盘/复盘台账.csv`，**幂等判据 = 最后一行日期是不是今天**（同日重复调用原地更新、不追加轮次），**未传 `--结论`/`--milestone` 保留旧值**。**⚠️ 只汇总事实，不做角色 judgment**——`--assemble` **不评判哪个角色好/差、不下"该裁谁"的结论**，职责调整的判断归**本主控与用户**（这是"给数不给令"边界的同一根线）；**到点仍无人回的结论记「未获确认」，不得写成"通过"**（BMAD「无人类决定 = 未接受」与用户「逾期默认通过」的政策冲突**待用户裁决**，本轮只实现无争议的那一半）。`python scripts/tests/test_retro_calibrate.py` 全绿（**96 断言**：两列正交、`landed`+逾期并存仍退出 1、已落地数不被逾期污染、`--close` 保留旧结论、缺失来源记"未查过"、GBK；把证据判定改坏有 5 条变红、把缺失来源处理改坏有 3 条变红）。
