# 思路文档模板（v3.7.0，复制后填内容，勿直接编辑）

> 落盘路径（v3.17.0 卡卷宗）：**卡内工作写在自己的卡目录**——`project-state/需求卡/card-NNN/思路-<角色>.md`（卡级验收/设计/开发）或 `project-state/测试卡/tc-NNN/思路-<角色>.md`（系统级测试轮）；**跨卡共性主题**用 `project-state/思路/<角色>/通用-<主题>.md`；无对应卡的盘点类工作用 `project-state/思路/<角色>/盘点-<主题>.md`。
> 写作时机：开工（置 in_progress）先写 ①~④ 再动手；完成/阻塞时补 ⑤~⑥。要点式、证据式，禁止事后编造——⑤⑥ 段如实记录与计划的偏差。

```markdown
---
role: 前端开发            # 本文档角色
object: card-169          # card-xxx | T-xx | 通用-<主题> | 盘点-<主题>
req: REQ-x.y              # 关联 PRD 需求编号（无则写 测试问题/CR 等）
tasks: [T-49]
created: 2026-08-29
updated: 2026-08-29
status: in_progress       # in_progress → done / blocked（与卡片状态联动）
---

> L0 摘要：<一句话：本卡本角色"怎么想、为什么"（≈100t）>

## ① 任务定位

- 卡片：card-169（测试问题-015）｜REQ/来源：测试问题跟踪
- 本角色切面：一句话说清「在我的职责上，这是个什么问题」（如：客户端 LLM 函数清单注入格式与解析器不匹配，导致函数定义整体丢失）

## ② 需求解读与现状事实

- 读过什么：card-xxx / 契约/api.yaml / 记忆/d-xxx / 代码文件（全部带 文件:行号 证据）
- 关键事实：编号列出（事实 1、事实 2……每条附证据）
- 根因链：按因果顺序写清（A → B → C），与卡片「证据/复现」互相印证而非复制

## ③ 方案与取舍

| 方案 | 思路 | 优点 | 代价/风险 |
|------|------|------|----------|
| A（选） | ... | ... | ... |
| B | ... | ... | ... |

- 选择理由：为什么 A
- 反例/边界自查（对抗性审查，≥1 条）：XX 场景下 A 会怎样 → 结论

## ④ 实施计划

- 预计改动：文件/接口/数据清单（含预计体量，对照任务切片硬指标 ≤5 文件）
- 步骤与验证：step1 → 验证方法；step2 → 验证方法……
- 依赖：需要谁先完成 / 哪些环境（对照 契约/环境.md）

## ⑤ 执行记录

> v3.16.0 留痕指针：详细执行动作/坑以卡片「进度日志」区块为准，**本段写结论性摘要并引用**（"见卡片进度日志 YYYY-MM-DD 行"），不重复展开。

- 实际做了什么（关键动作 + 提交号/命令）
- 坑与临时决策：遇到什么、怎么处理的、是否需要回写记忆

## ⑥ 结果与偏差

- 交付：实际交付物（对照卡片 AC 逐条）
- 与计划的偏差：哪里没按 ④ 走、为什么
- 遗留与经验：遗留事项（转 CR/新卡/记忆）、本次可沉淀的通用经验
```

## 各角色差异化要求（在六段框架内的侧重）

| 角色 | ② 现状事实侧重 | ③ 方案侧重 | ⑥ 结果侧重 |
|------|---------------|-----------|-----------|
| 前端开发/后端开发 | 代码事实（文件:行号）、复现取证 | 技术方案对比、影响面/回滚 | 改动清单、构建与运行证据 |
| 测试工程师 | 用例现状、覆盖缺口、环境口径 | 用例设计依据、覆盖矩阵、风险边界 | TC 执行结果逐条、缺陷归属建议 |
| 安全审计 | 威胁面、历史闸门状态 | 审查清单与抽检方法 | 发现与风险等级（P0~P3）、修复建议 |
| 代码解析师 | 结构/依赖/技术债事实 | 可复用资产与迁移路径 | 资产清单、风险提示 |
| 集成工程师 | 契约 vs 实现核对点 | 核对方法与判定标准 | 一致性结论、偏差清单 |
| 架构师/产品经理 | 约束与决策上下文 | ≥2 方案对比 + 裁决理由（与决策日志互链） | 裁决落地情况、反例验证 |
| UI设计师 | 现有 UI/规范差距；**走查期的实际渲染事实（截图/实际色值/断点表现）** | 设计方案与规范依据；**走查判据（域7 + 设计稿「走查对照点」）** | 产出物路径、设计确认结果、**走查结论（pass/fail + 证据指针）** |
| 运维工程师/项目经理 | 环境/进度事实 | 执行顺序与依赖 | 环境证据/进度结论 |
