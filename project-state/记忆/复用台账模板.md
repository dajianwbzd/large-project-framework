# 复用台账模板

> 项目经理维护 ｜ **一项目一份** ｜ 落点：`project-state/记忆/复用台账.md`（**先例复用评估的唯一判定留痕**）
> **为什么要它**：同一个团队用同一套范式做过很多工作台，**上一版做过的需求卡、测试卡、契约、组件、代码就在隔壁**；
> 但框架此前只有一条冷冰冰的禁令——「A 项目的角色/子代理禁止读写 B 项目根」，**没有任何机制把"隔壁做过了"变成开工前的一个动作**。
> 于是"重新造"不是谁的决定，而是**没有字段、没人需要做那个决定**的默认结果（同 #49 的根因写法）。
> 本台账把「复用 / 改造 / 不复用」变成**开工前必须落盘的判定**：可数、可核、可被下一个项目继承。
> 扫描器（只读）：`python -X utf8 scripts/reuse_scan.py <项目根> --write` → 候选资产清单落 `project-state/复用盘点-<日期>.md`
> 检查器（三态退出码）：`python -X utf8 scripts/reuse_scan.py <项目根> --check`
> ——**0 = 干净 / 1 = 有 ERROR / 2 = 无法检查（不是"没问题"）**。
> 机器只读下面的 `<!-- machine:reuse -->` 围栏块。

## 1. 六条纪律（先读这一段）

- **先扫后判、扫描在建卡之前**：`reuse_roots`（本项目 `config.json` 里声明的历史项目根）**没问过用户就动手 = 没查过**——
  缺这个键报 **ERROR `REUSE-ROOTS-MISSING`**（"没问过"≠"没有历史项目"）；用户确认确实没有历史项目时写**显式 `[]`**，
  并在《项目计划》或《主控工作计划》注明依据（记 INFO 豁免）。**声明的根在本机不存在只记 WARN**（NAS 可能没挂上），
  **不得把它读成"没有历史项目"**（同通用铁律②：查不到 ≠ 查过且干净）。
- **判定只有三值，且"不复用"要写得出依据**：`reuse`（直接复用）｜`adapt`（改造复用）｜`reject`（不复用）。
  **`reject` 的 `evidence` 必须写清为什么不划算**（契约不兼容 / 适配成本 > 重做 / 技术栈不同 / 质量不达标），
  **"没想到"不是依据**；`reuse`/`adapt` 的 `target` 必须写清落到本项目的哪张卡、哪份契约、哪个代码路径——
  判定不留落点，等于**声明了一个从不兑现的复用**（v5.5.0 假保护教训）。
- **卡与台账必须说同一句话**：需求卡 frontmatter 的 `reuse` 必须等于 `reuse_ref` 指向的那条台账行的 `verdict`
  （不一致 → ERROR `REUSE-CARD-LEDGER-MISMATCH`）；`reuse: new` 的卡 `reuse_ref` 必须是 `-`。
  **卡的字段不是建卡时随手填的**：它由评估产出，先有台账行、后有卡字段。
- **只读历史项目**：扫描器**只读**，绝不写任何历史项目的任何文件；**跨项目隔离仍然生效**——
  本条是把「跨项目复用」从禁令升级为**受控的只读通道**：扫描器自动读，**需要搬运资产时由主控显式搬运 + 在决策日志登记来源**
  （`agent.md` 统一路径管理第 3 条原有口径不变，写入方向仍禁）。
- **复用不是目的**：判据是**净收益**——复用省下的工作量必须大于适配、验证与理解成本。
  为了"复用率好看"硬套一个不兼容的旧契约，比新造更贵（**复用率不是 KPI**；机器只核"判过、对得上、有落点"，**不判判得对不对**）。
- **不删历史判定**：`RU-NNN` 全局唯一、升序、**只增不改**；判定被推翻时**追加一行新判定**并在 `evidence` 里指回被推翻的行，
  旧行保留（台账是账，不是当前状态表）。

## 3. 机读块（必须有）

```text
<!-- machine:reuse -->
id | date | source_project | source_ref | kind | verdict | target | evidence
RU-001 | 2026-10-09 | 示例工作台A | 需求卡/card-012 | 需求卡 | adapt | card-003 | //nas/work/示例工作台A/project-state/需求卡/card-012/card.md
RU-002 | 2026-10-09 | 示例工作台B | 契约/设计域.md | 契约 | reuse | 契约/设计域.md | //nas/work/示例工作台B/project-state/契约/设计域.md
RU-003 | 2026-10-09 | 示例工作台C | repos/skill-platform | 代码 | reject | - | 本项目无商城面，需求卡 card-001 的 not_doing 已排除
<!-- /machine:reuse -->
```

列义（**8 列，顺序固定**；检查器逐字匹配列头）：

- `id` = `RU-NNN`（**全局唯一、升序、只增不改、永不复用**；格式 `RU-` + 3 位数字）
- `date` = 判定日期 `YYYY-MM-DD`
- `source_project` = 来源项目名（**不许空**）——历史项目的 `config.json` 的 `project_name` 或目录名
- `source_ref` = 来源资产指针（**不许空**）——相对**来源项目根**的路径：`需求卡/card-012` ｜ `测试卡/tc-001` ｜ `契约/设计域.md` ｜ `repos/skill-platform` ｜ `代码/测试/用例库.md` ｜ `记忆/知识沉淀.md#k-004`
- `kind` = `需求卡` ｜ `测试卡` ｜ `契约` ｜ `组件` ｜ `代码` ｜ `脚本` ｜ `知识`
- `verdict` = `reuse` ｜ `adapt` ｜ `reject`
- `target` = 落到**本项目**的落点（卡号 / 契约相对路径 / 代码相对路径）；**`reject` 写 `-`**；`reuse`/`adapt` 写 `-` 记 ERROR
- `evidence` = 依据或证据（**不许空**）：`reject` 写为什么不划算；`reuse`/`adapt` 写来源文件的真实路径（**悬空指针 = 假证据**，同 #51 的锚点纪律：只有路径部分参与机核，行号不核）
- **字段内不许出现 `|`**（列分隔符）；要写多个用 `,` 或 `/`
- **同一个 `source_ref` 允许被多行引用**（不同卡复用同一来源是合法的）；只有 `id` 必须唯一升序

## 4. 三个角色怎么分（评估的执行顺序）

1. **项目经理**（主持 + 记账）：先问用户历史项目根 → 写 `config.json` 的 `reuse_roots` → 跑扫描器 → 建 `记忆/复用台账.md` →
   把产品经理与架构师的判定**逐条登记**（`RU-NNN` 新号）→ 出「复用 vs 重造」的净收益对比（省下什么 / 要适配什么）。
2. **产品经理**（需求侧）：拿扫描出的历史**需求卡 / 测试卡 / 用例库**与本次需求比对，产出**复用清单**——
   直接复用（AC 与契约原样可用）｜改造复用（写明差量面与口径差异）｜不复用（写明依据）；结论落 `思路/产品经理/盘点-先例复用.md`。
3. **架构师**（技术侧）：拿历史**契约（技术栈 / 数据模型 / api.yaml / 代码风格）+ 组件 + 代码模块 + 项目自建脚本**，
   评估可复用性与适配成本（依赖、版本、接口形状、许可），结论落 `思路/架构师/盘点-先例复用.md`。
4. **回填**：判定结果回写每张需求卡的 `reuse` / `reuse_ref`（**先有台账行、后有卡字段**）；
   产品经理建卡时对 `adapt` 卡额外写明**差量**，对 `reject` 卡写明**不划算的理由**。

> 角色分工的唯一事实源是 `skills/项目经理/SKILL.md` §22、`skills/产品经理/SKILL.md` §14、`skills/架构师/SKILL.md` §13。

## 5. 与其它文件的分工（别互相替代）

- `记忆/复用台账.md`（本文件）：**判定与落点**（跨项目累积；下一个项目会读它，形成链式复用）
- `复用盘点-<日期>.md`：**扫描器的只读候选清单**（机器生成、可重复生成；是线索不是结论）
- `思路/项目经理/盘点-先例复用.md`、`思路/产品经理/盘点-先例复用.md`、`思路/架构师/盘点-先例复用.md`：**三角色的推导过程**（六段模板）
- `记忆/知识沉淀.md`（`k-xxx`）：**可复用的技术知识与模式**沉淀（面向所有后续项目，不限本机制）
- `记忆/决策日志.md`（`d-xxx`）：**搬运资产**（把历史项目的文件复制进本项目）时登记来源

## 6. 诚实边界

- 检查器只核**声明与台账自不自洽**：`reuse_roots` 有没有声明、机读块列头/取值/编号、卡与台账是否一致、指针是否悬空。
  **核不出**：扫描器有没有真的扫到该扫的项目、相似度排序是否合理、这条判定**判得对不对**（净收益是人的判断）、
  台账里写的来源项目**是否真的存在**（NAS 没挂上时只能核"声明过"）、`evidence` 里的文本是否站得住。
- **相似度不是结论**：扫描器的分数只是**字符 n-gram 重合度**，用于排序线索，**不做语义理解**——
  "分数高"不等于"该复用"，"没扫到"不等于"没做过"（历史项目可能没按本范式留痕、可能不在声明的根里）。
- **本项目本版只做「同范式历史项目」复用**：开源社区（GitHub 同类项目）检索与代码复用是**第二期**，本版不留半成品代码，
  只留这条边界——真要开工时按新机制立项（新检查号 + 新脚本），**不许在本机制里顺手夹带**。
- 参数（`--depth` 默认 3、`--limit` 默认 200、相似度权重）来自 2026-10-09 对真实 NAS 工作台工程的标定，**换盘位/换项目结构要重标**。
- **本版不改任何真实历史工程的数据**：扫描全为只读；对拍证据只到文件级（mtime / 哈希）。
