# 关键决策日志（ADR 风格）

> 各角色在做出关键决策后追加记录（为什么选 A 不选 B）。决策可追溯是本框架的核心要求。
> 编号规则：`d-xxx` 递增；关联需求卡的条目会被卡片「相关记忆」区引用。
> 格式遵循 ADR（Architecture Decision Record）：**背景 / 决策 / 理由 / 备选方案 / 后果**——记录的是"为什么"，而非只记结论。

## d-001 <决策标题>

- **状态**：Accepted / Superseded by d-XXX / Deprecated
- **日期**：
- **加载优先级**：高 / 中 / 低（规则级 / 项目级 / 任务级）
- **决策者**：
- **关联卡片**：card-xxx（如有）
- **背景**：<为什么需要此决策>
- **决策**：<决定了什么>
- **理由**：<为什么选这个>
- **备选方案**：<评估过的其他选项，含被否决原因>
- **后果**：<影响、代价、后续注意点>
- **来源**：<如有官方文档/调研依据，注明 URL + 锚点>

> 规则：
> - **不删除旧决策**（承载历史背景）；决策改变时新增一条 d-xxx 并让旧条目标记 Superseded
> - **非平凡决策**须先经受对抗性审查（"哪里可能是错的？"至少 2 个反例）再落笔
