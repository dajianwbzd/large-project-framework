# 系统交付报告（面向用户/客户）

> 本报告由**项目经理**在验收合并（GO/NO-GO）后、SHIP 前产出，面向**用户/客户**（非技术视角优先）。它不是角色日报的堆砌，而是"这个系统现在到底怎么样了"的综合陈词。产出到 **`交付/交付报告.md`**（v3.18.0：对外文件进客户交互区 `交付/`，不放 `project-state/`）。

## 一、一句话结论（客户可读）
> 例：本次迭代完成 XX 个需求，系统已在测试环境通过三路验收（功能/集成/安全）+ 界面还原走查，可上线；全平台无 Critical 缺陷，有 N 项待修的高/中风险项（见第四节）。

## 二、系统做到什么程度
| 项 | 说明 |
|----|------|
| 交付范围 | 本次完成的需求清单（DONE 卡片号 + 一句话功能） |
| 里程碑 | 当前阶段（阶段 0~5）、完成度 |
| 运行环境 | **dev / test / prod 三环境状态**、三库验证结论（test 以 prod 同步脱敏数据验收、prod 变更走 SQL 申请单，见 `契约/环境.md`、`契约/数据模型.md`） |
| 未纳入 | 本次范围外的需求/功能（明确边界，避免客户误解） |

## 三、质量与验收结论
| 维度 | 结论（GO/NG） | 依据 |
|------|--------------|------|
| 功能正确性 | … | 测试报告（`代码/测试/测试报告.md`） |
| 前后端契约与集成 | … | 集成报告（`进度/集成工程师.json`） |
| 安全性 | … | 安全审计（`问题/安全问题/审计报告.md`） |
| 部署就绪 | … | 运维（`代码/部署/` + `进度/运维工程师.json`） |
| **系统级（跨卡一致性，v3.17.0）** | … | 测试卡收口结论（`测试卡/tc-NNN/tc.md`：覆盖维度 + 发现项归属汇总） |

**验收合并结论**：`overall.json` 的 GO/NO-GO；critical/high 缺陷回退情况。

## 四、风险与待办（对客户透明）
| 风险/待办 | 级别 | 影响 | 建议 |
|---|---|---|---|
| … | Critical/High/Medium/Low | … | 尽快修复/本迭代/纳入 Backlog |

## 五、怎么验证（给用户/客户的操作指引）
- 环境入口：test 环境地址（部署/接口/前端 URL）
- 复现关键路径：给出 1~3 条端到端验证步骤（登录→业务→结果），并指向对应测试用例与最近一轮测试卡的覆盖矩阵（`测试卡/tc-NNN/覆盖矩阵.md`）
- 证据可查：各角色报告的落盘路径（供客户/审计抽查）

## 六、交付边界与后续
- 运维责任 / 上线流程（走「发布前清单」与 SHIP 门禁，见 `进度/overall.json`）
- 已知限制 / 后续迭代建议
- 审核记录：`问题/审核记录.md`（本轮穿透审核的 pass/存疑/fail 汇总）

> 模板使用：取代逐条转述各角色报告（转述 = 信息损失）。本报告是**综合陈词**，细节在对应角色报告里，需要深挖时按第四节路径跳转。
