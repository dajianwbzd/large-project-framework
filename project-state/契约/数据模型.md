## 环境执行状态（三库登记，v3.8.0）

> 后端开发产出迁移、运维工程师维护执行状态。**每张迁移必须在 dev / test / prod 三库分别执行并登记**，三库各自独立、禁止跨库引用。未在目标环境登记的迁移不得进入该环境上线。

| 迁移编号 | 说明 | dev 执行 | test 执行 | prod 执行 | prod 申请单 | 登记日期 | 备注 |

> - **三库隔离**：dev/test/prod 各自独立库（或独立 schema），`DATABASE_URL` 互不相同，禁止把 test 迁移状态当作 prod 已执行。
> - **test 数据源（v3.8.0）**：test 库数据 = 定期从 prod 同步的正常功能数据（脱敏）为主，seed 补充；迁移先在 dev/test 验证通过，再走 prod 上线。
> - **prod 严格管理（v3.8.0）**：prod 库执行迁移/数据修复必须先提交 **SQL 修改申请单**（目标表/变更内容/影响范围/回滚方案，编号 SQL-NNN），经运维 + 项目经理审批后才可执行；未获批禁止动 prod 库，不做破坏性操作。
> - **登记即证据**：上线前核对此表，确认本卡涉及的全部迁移已在目标环境（test/prod）执行登记且 prod 项附申请单编号，缺一不可上线。
