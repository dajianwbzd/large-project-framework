# 浏览器资源调度规程模板（Browser Resource Scheduling Template）

> 用途：**共享浏览器实例的取用—归还规程** —— 一个项目**最多复制一份**到 `project-state/契约/浏览器资源调度规程.md`，按本项目端口/卡号/时长裁剪后生效；它管"**谁在什么时段用这唯一的浏览器实例、怎么取、怎么还**"。
> 引用：`契约/环境.md`（环境与端口口径）、`契约/上下文索引.md`（文档登记与【模板】图例）、`测试卡/测试卡模板.md`（机读块体例）、`代码/测试/用例库模板.md`（机读块列义写法）。
> 维护：**集成工程师**（本模板随框架发；项目内那一份由集成工程师维护，配额变更走 CR）。
> 依据：`agent.md`「任务执行纪律」17（**验证工具按宿主选、优先用宿主内置能力**）——**工具口径本体只在那一处，本文件只写调度纪律，不复写工具名清单**。

---

## 1. 为什么要这份规程（事故背景，30 秒版）

`2026-09-29` 某真实工程出过一次**浏览器共享资源失控**事故：三名队友**并行各起会话**、**各开 7～15 个 tab**，
把用户 Chrome 的**扩展 service worker** 拖垮 —— `bsk logs` 反复 `reaping unresponsive browser` 与 `session removed`，
所有人的会话一起断。事后复盘定案：**根因在编排层**——**下发指令时没指定仲裁者、没划独占时段**，
**不是"某个队友不小心"**。

> **一句话总则**：**同一时刻，只有 1 个会话、1 个角色独占浏览器实例；用完必须归还，禁止遗留会话。**

**为什么必须由框架管**：浏览器实例（经宿主工具接用户真实 Chrome profile）是**跨端共享资源** ——
前端/后端/数据/验收各条线取证都要用**同一个实例、同一份登录态**。它不是"每人一份的本地工具"，
而是**一个实例、一个扩展 SW、一份心跳预算**；被大量 tab 拖垮就会被守护进程判死并回收，于是**所有人的会话一起断**。
⇒ **这是共享资源争抢的必然结果，不是"通道坏了"。**

> **引入版本**：本模板 v5.11.0 引入（框架侧引入版本只标注在此处，文件头一律不写版本号）。

## 2. 角色三分工（**仲裁权归集成工程师**）

| 角色 | 在浏览器资源上的职责 | 落点 |
|---|---|---|
| **项目经理** | **定预算**：会话数上限、单会话 tab 上限、占用时长上限、**归还判据**；把预算写进**卡 / 派发简报** | 需求卡 `card.md` 验收标准 + 派发简报 |
| **集成工程师** | **共享实例的仲裁者**：发放取号、划分独占时段、强制清场、故障封盘 | 本文件 + 派出记录 |
| **使用者**（开发 / 测试 / 验收各角色） | **按预算取用、收工归还**；不得自行抢占，不得超预算 | 卡内证据 + 取用—归还机读块 |

**为什么仲裁者是集成工程师（理由必须写清，别只写结论）**：

共享实例的争抢面是"**多端同时抢同一个浏览器 + 同一份登录态**"（展示端 / 管理端 / 供应链端都要取证），
而这正是框架里 **前后端联调 / 多服务对接 / 契约争议 / 合并冲突裁决 → 集成工程师** 的**既有职责边界**：
一个资源被多方同时索要、又只能串行发放 ⇒ **本身就是"集成"问题**，不需要新设角色。
⇒ **故浏览器实例的发放与回收归集成工程师仲裁，不归各自协商。**

**禁止事项（对所有人）**：

- ❌ **重启用户的 Chrome / 改扩展配置 / 卸载重装扩展**（会丢用户全部标签页与登录态，而共享实例存在的意义正是复用登录态）；确需用户操作 → **上报主控转请用户**。
- ❌ **自起浏览器进程 / 开远程调试端口 / 用一次性自动化实例**（红线见任务执行纪律 17 ③；批处理脚本除外且必须用**持久 profile**）。
- ❌ **绕过仲裁自行开会话**。
- ❌ **跨项目复用同一实例**（本项目未登记的资源不借）。

## 3. 独占时段机制

| 项 | 定档 |
|---|---|
| 粒度 | **单会话串行；同一时刻全局最多 1 个会话** |
| 单次占用 | **≤ 8 分钟**（含健康检查与取证） |
| 联合时段 | 多角色需同时在场时用，**≤ 12 分钟**（仍只开 1 个会话，见 §3.1） |
| 取号 | 向仲裁者申请；仲裁者维护队列并广播「**当前占用者 + 截止时刻**」 |
| 超时处理 | 到期未完成 → **立即** `session stop` **交还**，排到队尾重排；**严禁超时后自行续期并行硬跑** |
| 强制清场 | 仲裁者可随时 `bsk session stop --all` 回收（有人违规或卡死时） |
| 排队优先级 | **卡住他人验收的 > 补单张证据的 > 优化类取证的**（"阻塞别人"优先于"完善自己"） |
| 仲裁者自约束 | **放行时段时必须记下截止时刻；到点无论完成与否，先收口**（否则"放行"会退化成"长时间挂起"） |

### 3.1 联合时段（多角色需同时在场时的例外形态）

当一项取证**必须两个角色在同一个实例上完成往返**时，用**联合时段**：仍只占 **1 个会话**，故不违反"同一时刻一个会话"。

| 项 | 规则 |
|---|---|
| 适用条件 | 跨端口闭环、提交流转审核、需同一份本地存储上下文才看得见的联动 |
| 会话归属 | **仍只开 1 个会话**，由**发起方**持有会话 id，**共享给协作方** |
| 时长 | **≤ 12 分钟**（往返 + 双方各留证据更费时） |
| 为什么不能拆成两段 | **中途 `session stop` 会丢上下文**（例：提交的那条记录要靠同一份 localStorage 才能在审核端口看见） |
| 排期位置 | 排在两个角色各自的单独时段**之后**，避免同一角色连续占用过久 |
| 冻结要求 | 时段内**被测代码冻结**（临改会让时段验的版本与最终版本不一致，证据作废 → 中止时段、改完重排） |

## 4. 配额（**单会话 tab ≤ 3**）

| 配额 | 限值 | 理由 |
|---|---|---|
| 同时活动会话数（全局） | **1** | 扩展 SW 心跳是共享瓶颈 |
| **单会话 tab 数** | **≤ 3** | **每个 tab 都占扩展 SW 唤醒与 CDP 会话槽；7～15 个必然拖垮** |
| 单角色故障时自发重试次数 | **0 次** | 见 §7 封盘规则 |
| 重操作（全页截图等） | **超时立刻收手，不许连试** | 重操作是 SW 最重的活，连试会把 SW 直接打死 |
| 跨会话复用同一 tab | 禁止 | 抢别人正在看的页面（见 §6.2） |

> **预算由项目经理定、执行由使用者守、仲裁者有权收紧**：故障降级期，仲裁者可临时把配额压到更严（如单会话 1 tab、禁重操作）后再放行。

> **预算落在字段上（检查器只认字段）**：卡与测试卡的 frontmatter 由项目经理写 `browser_tab_cap`（默认 **3**，即上表"单会话 tab 数"）与 `browser_window_minutes`（默认 **8**，单段取用时长上限）；正文 `machine:browser` 机读块的 `tabs` 不得超前者。**没有这两个字段 = 预算没人批过**——`python scripts/browser_resource_audit.py <项目根>` 对"卡里用了浏览器却没声明 `browser_tab_cap`"记 WARN **`BRW-TAB-CAP-UNDECLARED`**（默认值不写在卡上，等于没人知道这一卡批了多少）。

## 5. 开—关配对（**本模板的核心**）

> **铁律：只写"开"不写"关"＝未收口。** 拿不到"归还"这一步的证据，这个时段视为**未完成**，
> 而不是"差不多做完了"。**一个时段的完成标志是"实例回到干净态"，不是"数据取到了"。**

### 5.1 开（取号后，三步都要）

1. **取号成功**（仲裁者已放行，且记下截止时刻）；
2. **开会话并拿到会话 id**——**真 id 在 stdout**（见 §6.1），**不是你起的名字**；
3. **健康三连通过**（见 §5.3），再动第一下取证。

### 5.2 关（时段结束，**三步一步都不能省**）

| 步 | 动作 | 判据 |
|---|---|---|
| ① | `tab close` —— **逐个关掉自己开的 tab** | 自己没有遗留 tab |
| ② | `session stop` —— 停会话、交还实例 | 会话号已消失（**注意位置参数，见 §6.2**） |
| ③ | `session list` —— **自检** | **不能有自己的会话**（只见他人的或 `(no active sessions)`） |

> **交付前自检铁律**：`session list` 里**不能有你自己的会话**；交不回资源的时段视为**未完成**。
> **收工交还 = ①+②+③ 三样齐**；只做 ①② 而没自检，等于**没配对**（机读块里的 `return` 也不许填）。

### 5.3 健康三连（只有三连全过才算通道可用）

| # | 判据 | 通过标准 | 口径 |
|---|---|---|---|
| ① | `bsk doctor` **全绿** | 各项 `ok` | 宿主工具自检 |
| ② | `session start` **拿到 4 字母会话 id** | 返回码 0，且 stdout 是 4 字母串 | **真 id 在 stdout** |
| ③ | **活过 30 秒且 `tab create` 成功** | 30 秒后 `session list` 仍有该 id；`tab create` 返回 `tab_id` | **③ 不可省略** |

> **只绿 doctor 不算好**：已实测到「`doctor` 全绿但会话活不过几秒」的**假健康**。
> 健康检查的**命令与参数按宿主口径取用（见任务执行纪律 17）**，本文件不复写工具名与 CLI 细节。
> **归因纪律**：三连失败时**先排除用法错（§6 三个坑），再判通道健康**——**两类都要查，不是二选一**。

## 6. 三个坑（**原样保留，它们是"清不掉"类故障的头号成因**）

### 6.1 坑 A：`--name` 不是会话 id

启动会话时给的名字**只是"本地操作历史里显示的任务名"**；**真正的会话 id 是 stdout 打印的那个 4 字母串**。
**把 `--name` 的值当会话 id 用**，必然报：

```
error: requested resource does not exist
details: session not registered or already stopped
```

> ⚠️ **这个报错极易被误判为"通道坏了 / 会话活不过几秒"**——它字面说"会话不存在"，
> **实际是"你给的 id 不存在"**。⇒ **先自查 id 拿没拿对，再谈通道故障。**

### 6.2 坑 B：`session stop <SID>` 是**位置参数**

| 命令 | 传会话 id 的方式 |
|---|---|
| `session stop <SID>` | **位置参数**；写 `--session` 报 `unexpected argument '--session' found` |
| `tab create` / `tab close` / `tab select` | `--session <SID>` |
| `screenshot` / `evaluate` / `snapshot` / `observe` | `--session <SID>` |

> ⚠️ 照抄 `session stop --session X` → **会话停不掉** → **遗留会话堆积** → 后续所有人抢资源。
> **这是"清不掉"类故障的头号成因。** 另可直接 `bsk session stop --all` 兜底。

### 6.3 坑 C：`evaluate` 表达式必须用 PowerShell 停止解析符 `--%`

表达式含 `$` `;` `{}` 等字符时会被 PowerShell 抢先解析，一律加停止解析符：

```powershell
bsk --% evaluate --session <SID> --tab-id <TID> "document.title"
```

### 6.4 附加禁令：**禁 `navigate`，一律 `tab create`**

`navigate` 作用在**会话的活动 tab** 上，会把**别人正在看的页面顶掉**（抢 tab）；
`tab create` 是隔离的新 tab，不干扰他人。**取数一律 `tab create`。**

## 7. 故障封盘规则

**通道不可用时：立即封盘，禁止各角色各自重试刷屏。**

1. **第一次失败即停手**；**严禁连试**——连试只会加重扩展负担，把"可恢复的降级"变成"真死"。
2. 跑**一次**只读三连诊断并**留存输出**：`doctor` / `browsers` / `session list` / `logs`(tail)
   （命令与参数**按宿主口径取用，见任务执行纪律 17**）。
3. **上报仲裁者**（集成工程师），**抄送主控**；内容含：**卡号、时刻、命令、完整报错原文、诊断输出**。
4. 仲裁者裁决：
   - **降级可用** → **限配额**（如单会话 1 tab、禁重操作）后放行；
   - **不可用** → **封盘**，广播"暂停浏览器取证"；各角色**转做不依赖浏览器的工序**，**等待自动恢复，不人工干预 Chrome/扩展**。
5. **禁止**为"显得能干活"而硬跑或编造证据。**通道不可用就明确报不可用。**

> **静默期**：封盘后**至少 3 分钟**不再发起任何开会话动作，让扩展 SW 完成重连与心跳恢复。
> **责任纪律**：报「未生效/不可用」时**现象与归因必须分开陈述**——"我这边没拿到数据"是现象，
> "工具坏了"是归因；**归因错就是这么来的**。

## 8. 机读块规范（**必须与检查器对齐**）

卡 / 测试卡正文里的**取用—归还记录**用下面的 **7 列机读块**；**列头一字不差**：

```text
<!-- machine:browser -->
| id | card | session | tabs | take | return | evidence |
| BRW-001 | card-013 | xyza | 3 | 2026-09-30 10:00 | 2026-09-30 10:07 | 需求卡/card-013/证据/前端/会话.md |
<!-- /machine:browser -->
```

列义（**7 列，顺序固定**）：

| 列 | 含义 | 约束 |
|---|---|---|
| `id` | `BRW-NNN` | **全局唯一且升序**（只增不减、永不复用） |
| `card` | `card-NNN` / `tc-NNN` | **写了就必须真实存在**（指向不存在的卡 = 悬空登记） |
| `session` | 当次会话 id（示例 `xyza`） | **中性值即可**，本模板不写具体会话号 |
| `tabs` | 该会话同时开过的 tab 数 | **`tabs > 3` = 超预算** |
| `take` | 取用时刻 `YYYY-MM-DD HH:mm` | 与独占时段起点一致 |
| `return` | 归还时刻 `YYYY-MM-DD HH:mm` | **空 = 取用未归还（检查器报 ERROR）** |
| `evidence` | 证据路径指针 | 相对 `project-state/` 或项目根 |

**机器判定口径（**唯一检查器**）**：`python scripts/browser_resource_audit.py <项目根>`

| 退出码 | 含义 |
|---|---|
| **0** | **才算过**（声明自洽、取用已归还、无跨卡时段重叠） |
| **1** | **有 ERROR**（`return` 空 / `tabs > 3` / 跨卡时段重叠 / 列数不符 等） |
| **2** | **没有任何卡 = 「无法检查」，不是「没问题」** |

> **跨卡时段重叠 = ERROR**：两条 `BRW-NNN` 的 `[take, return]` 落在同一时刻 ⇒ 违反"同一时刻全局最多 1 个会话"。
> **退出码 2 的读法**：它**不是通过**，而是"**没有可检查对象**"——报"检查通过"属于**假绿**。

## 9. 事故教训摘要（**供后人不再踩**）

1. 三人并行**各自开会话**，**未指定仲裁者、未划独占时段**（编排层真因）。
2. 各会话**各开 7～15 个 tab**（有人自陈开 12 个），直接超出扩展 SW 承载。
3. 扩展 SW 心跳停摆（`idle_secs=66/68`）⇒ daemon 判死回收：`reaping unresponsive browser`。
4. 自动重连反复发生（`generation` 1→2→3 递增），日志 `session removed` 刷屏；队友观感即"会话活不过几秒"。
5. 叠加两个 CLI 用法错（§6.1 `--name` 当 id、§6.2 `session stop --session`）⇒ 停不掉 ⇒ **遗留会话堆积**，把局部故障放大成"通道全坏"的观感。
6. 故障后各自重试刷屏，持续给已过载的 SW 加压（**连试 6 次**是事故加重因素之一）。
7. **串行纪律（独占时段 + 单会话 1 个 + tab ≤ 3 + 用完即停）上线后，`reaping` / `generation` 递增事件不再复现**——这是"并发 tab 过载确是真实压力源"的**可复核反证**。
8. **根因是编排层没指定仲裁者与独占时段**（不是"某个队友不小心"）；用法错只是**放大器**，真实降级与用法错是**叠加**的两类原因，**单怪任何一方都是不完整的定性**。

## 10. 诚实边界（**机器核不了什么，写清楚**）

- **机器只核「声明与配对」**：`return` 有没有填、`tabs` 有没有超、跨卡时段有没有重叠、列头/列数对不对。
- **机器核不了**：**「会话是否真的被关掉」**、**「tab 是否真的关干净」**——
  这两件事只有**当时的 `session list` 自检输出**能证明；机读块填了 `return` **不等于**会话真的停了。
  ⇒ **`return` 非空 + 自检输出缺失 = 声明性通过，不是事实性通过**（同通用铁律：**没写清 = 未收口，不等于"没做过"**）。
- **机器核不了**「有没有偷偷自起浏览器进程」——靠证据自述 + 主控抽查。
- **本模板不含项目专有值**：不写具体端口 / 会话 id / 项目专名（示例一律用 `card-013` / `xyza` 这类**中性值**）；
  项目内复制后按本项目填端口与卡号，**端口/环境口径以 `契约/环境.md` 为准**。
- **与证据方法学无关**：本文件只管**资源调度**；"读数是否可信"的判据（版本校验、锚点、反 mock 等）**不在本文件**，
  那是测试/集成各自的取证纪律，**别把两件事混成一份**。

## 11. 速查卡（贴在手边）

```text
# 取号后 —— 开
```
