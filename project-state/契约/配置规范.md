# 配置规范（Config Standard）

> 版本：v1（随大型项目开发框架 v3.11.0 模板复制到项目）
> 本文件是「零硬编码」规则的落地标准：定义什么是配置、哪些必须进配置中心、哪些走环境变量、以及前后端如何载入。与 `api设计规范.md`（怎么设计接口）配套——本规范是"怎么配置"，`配置中心.md` 是"配置什么"。

## 1. 目标与红线

**目标：业务代码零硬编码**——接口名与关键常量不得以字面量散落在代码里，统一从配置载入。改一处配置即全局生效，避免"同一个 `/users` 在 8 个文件里出现 8 次，改一次漏 7 次"。

**三类值，三种去处**：

| 类别 | 例子 | 去处 | 载入方式 |
|---|---|---|---|
| 环境特定值 | 端口、数据库 URL、第三方 key、密钥 | `.env` / 环境变量 | 启动时读环境变量 |
| 跨模块接口名 | `/api/v1/users`、路由前缀、事件/队列/topic 名、表/表字段名、缓存 key 前缀、API 客户端端点 key | `契约/配置中心.md` | 配置模块载入，代码引用符号 |
| 业务常量 / 魔法值 | 分页大小、超时、重试、限流阈值、TTL、状态枚举、错误码、默认值、文案键 | `契约/配置中心.md` | 配置模块载入，代码引用符号 |

**红线（违反即视为契约违规，集成/安全/代码解析按 `代码复查规则库.md` 域6 打回）**：

1. 禁止在业务代码里写死接口路径字符串、魔法数字、重复出现的状态/错误码字面量、密钥。
2. 禁止同一接口名/常量在两个以上位置重复定义——只允许在配置中心定义一次，其余引用。
3. 密钥/凭据永不进代码、永不入库（`.gitignore` 排除 `.env`），一律走环境变量/平台 secrets。
4. 配置变更（新增 key、改默认值、删除 key）走 CR + 同步 `记忆/变更日志.md`（c-xxx），不静默改。

## 2. 配置中心（`契约/配置中心.md`）

单一事实来源（Single Source of Truth），按类别建表，键名用稳定的小写点分命名（如 `api.paths.users`）。**架构师在 `契约/配置中心.md` 注册初始值，开发按需增量登记——新增常量/接口名先登记再引用，禁止"先写死，后补配置"。**

分类表：

- **接口名注册表 `api.paths.*`**：端点路径、路由前缀、服务/消息 topic 名、表/字段名、缓存 key 前缀、API 客户端端点 key
- **常量表 `biz.*` / `pagination.*` / `cache.*` / `timeout.*` / `limit.*`**：业务、分页、缓存、超时、限流等默认值与上限
- **枚举与映射表 `enum.*` / `code.*`**：状态枚举、错误码（code/message 文案）、字典映射、i18n key
- **功能开关表 `feature.*`**：feature flag、灰度比例、可调开关
- **环境变量清单**：声明哪些键走 `.env`（变量名、含义、默认值、是否必填、是否敏感）

## 3. 载入规范（按栈）

配置必须**在启动时一次性载入**成类型安全的配置对象，业务代码只引用配置符号，不出现字面量。禁止在模块内"要用时再读一次环境变量/再拼一次路径"散落各处。

### 后端（Python / Node / Go）

- 用统一配置模块载入：`config.py`（Python）/ `config.ts`（Node）/ `config.go`（Go）。
- 配置模块职责：①读环境变量（`.env`/os.environ）填充环境值；②读配置中心填充业务常量；③对外暴露**类型安全访问器**（如 `CFG.api.paths.users`、`CFG.biz.pagination.default_size`）。
- 密钥用 pydantic-settings / os.environ，**绝不 import 成代码字面量**。

```python
# config.py
import os
from dataclasses import dataclass

@dataclass(frozen=True)
class ApiPaths:
    users: str = "/users"
    auth_login: str = "/auth/login"

CFG = ApiPaths(
    users=os.getenv("USERS_PATH", "/users"),
    auth_login=os.getenv("AUTH_LOGIN_PATH", "/auth/login"),
)
```

```python
# routes/users.py —— 引用配置符号，不写死
router = APIRouter(prefix=CFG.api.paths.users, tags=["users"])
```

### 前端（TypeScript / React / Vue）

- `src/config/index.ts` 为唯一配置模块：`import.meta.env.VITE_*` 读环境变量 + 常量集中导出；`src/config/constants.ts` 放静态常量表。
- API 客户端端点路径映射自配置（可由 `api.yaml` 生成类型，或集中常量表），组件里**禁止内联** `"/auth/login"` 这类路径字符串。
- 环境变量以 `VITE_` 前缀（Vite）或框架等价方式注入，前端不直接接触服务端密钥。

```ts
// src/config/index.ts
export const API = {
  baseUrl: import.meta.env.VITE_API_BASE_URL ?? "/api",
  paths: { login: "/auth/login", orders: "/orders" },
};
```

```ts
// 组件里 —— 用配置符号，不内联路径
await loginApi(API.baseUrl + API.paths.login, form);
```

## 4. 自检清单（开发置 done 前逐项过）

- [ ] 无字面量接口路径 / 路由前缀 / 事件名 / 表名散落在业务代码
- [ ] 无魔法数字（分页 / 超时 / 重试 / 限流 / TTL / 边界值）内联
- [ ] 状态 / 错误码 / 枚举 / 文案键从配置或常量表引用
- [ ] 密钥 / 凭据走环境变量，代码与仓库无明文
- [ ] 新增常量已在 `契约/配置中心.md` 登记
- [ ] 同一接口名 / 常量未在多处重复定义

## 5. 编辑流程

- 配置中心调整（新增 key / 改默认值）须提交 CR（说明影响面）+ 同步 `契约/配置中心.md` + `记忆/变更日志.md`（c-xxx）；改环境变量清单一并更新 `.env.example`（运维）。
- **破坏性改键名（删/改名）按「接口/常量弃用」处理**：先在配置中心登记 + 各引用点迁移，再移除旧键，禁止一步删除。
