# 设计域（design profile）

> UI设计师产出。**设计链的"域轴"**：声明本项目落在哪个界面域，从而决定"令牌如何落地、方向稿用什么载体、走查怎么取证、用什么判据"。
> 为什么需要它：设计链的**方法**（引导式追问 / 3-6 个完整视觉人格 / 用户选方向 / 命名主角旅程 / surface closure）跨域通用，但**载体与判据不通用**——把 Web 的 WCAG、浏览器断点、HTML 方向稿套到游戏或桌面上，会"跑得通但判错"。
> **L0 摘要**：本项目的设计域、技术栈，以及由此决定的导出目标 / 方向稿载体 / 走查取证与判据。

## 一、域声明（项目初始化时由主控 + UI设计师 共同定档，写入 `config.json`）

| 字段 | 取值 |
|---|---|
| `design_profile` | `web` / `desktop` / `mobile-native` / `game`（可多域，如 `desktop(Electron) + game(Unreal)`） |
| `design_stack` | 具体技术栈（决定导出目标与取证方式） |
| 定档依据 | 交付形态 + 运行环境；**档位未定不得开始设计**（对齐 `契约/环境.md` 的环境档位纪律） |

## 二、跨域不变量 vs 按域分叉（一张表看清哪里通用、哪里要换）

| 层 | **不变量**（跨域必须一致） | **按域分叉**（必须换） |
|---|---|---|
| 契约（DESIGN.md） | 令牌化（颜色/字体/间距/圆角/组件）· 令牌是单一事实源 · 下游只引用符号不抄裸值 | 令牌**导出目标**；**对比度判据**；单位与尺寸体系；**`game` 域另有 Art Tokens**（美术调色板 / 资产命名前缀后缀表 / 贴图尺寸与格式表 / texel density 与 poly 预算） |
| 契约（EXPERIENCE.md） | 信息架构 · 微文案语气 · 组件**行为**规格 · 状态模式 · 交互原语 · **命名主角**关键旅程 · surface closure 收口 | **"响应式"章节**（断点／窗口尺寸／分辨率与宽高比矩阵／设备与安全区）；**可访问性底线**的实现方式 |
| 共创（方向稿） | 3-6 个**完整视觉人格**（密度/字重/动效意图/品牌调性真实不同）· 含状态变体 · 真实内容禁 Lorem · 用户选方向 · 量级可对比 | **方向稿载体**；关注面清单（域特有维度）；**`game` 域另加美术方向板**（风格支柱/参考板/色彩脚本/剪影规则） |
| 验收（走查） | 独立于实现者 · **真实运行**取证 · 客观可证伪 · 严重度按下游影响 · 反偏见纪律 | **取证方式**；**判据集**；状态的种类；**`game` 域加 `art_lint.py` 资产门禁** |

## 三、各域 bootstrap 清单

> 深度定位：**薄**——只做到"不静默做错 + 该核的都挂上清单"。域内的 craft 细节留到真实项目里长（框架纪律：服务够用即停、不过早抽象）。

### 3.1 `web`（基线，已有完整实现）

- 导出目标：Tailwind v3 `theme.extend` / Tailwind v4 `@theme` / CSS 自定义属性 / W3C DTCG（`design.md export`）
- 方向稿载体：自包含 HTML（内联 CSS、零外网依赖）
- 响应式：320 / 768 / 1024 / 1440 四档断点
- 走查取证：内置 Browser Use 四档 × 关键状态截图
- 判据集：设计令牌落地（`代码复查规则库.md` 域7）· **WCAG 2.1 AA**（对比度/键盘/`aria-label`/焦点管理）· 组件三态 · 响应式不断裂 · 文案真实感
- 详细要求见 UI设计师 SKILL §共创期 / §验收期

### 3.2 `desktop`（Electron / Tauri）

> **关键利好**：渲染层是 Web 技术栈 → **`web` 的令牌链与判据主体可复用**（Tailwind / CSS 变量照旧）。桌面只需补"**平台层**"——窗口、菜单、快捷键、平台规范、原生辅助功能。

| 维度 | 必须设计与核对的内容 |
|---|---|
| **窗口管理** | 最小/默认尺寸与可否缩放 · 最大化/全屏语义 · 多窗口（何时开新窗口 vs 新标签） · 窗口状态记忆（位置/尺寸） · 分屏与贴边 |
| **菜单与入口** | 应用菜单栏（macOS 必居顶栏，Windows 在窗口内）· 上下文菜单 · 托盘/状态栏图标（含退出路径） |
| **键盘快捷键表** | 逐条列出并核对：**与系统/宿主冲突检查** · 可发现性（菜单里显示）· 可配置性 · 无鼠标可完成主流程 |
| **平台规范遵从** | macOS HIG（交通灯按钮/标题栏拖拽/全屏语义/⌘ 习惯）· Windows Fluent（边框/圆角/材质/标题栏）· Linux 桌面环境差异；**平台差异不得"一套皮打天下"** |
| **平台原生动量** | 双击标题栏最大化 · 拖拽区域 · 滚动惯性与右键行为 |
| **可访问性（换实现方式）** | **不用 ARIA 作为唯一手段**：Windows 走 **UIA**、macOS 走 **AX API**；核"辅助功能树可读 + 全键盘可达 + 焦点可见" |
| **本地与离线** | 本地数据/缓存/离线可用性 · 文件拖入与系统集成（打开方式/最近文件） |
| **安装与更新** | 安装包形态 · 自动更新提示时机 · 版本与回滚可见性 |
| **显示环境** | 多显示器与高 DPI · 深浅色跟随系统 · 系统字号缩放下的布局 |

- 导出目标：Web 令牌链（CSS 变量/Tailwind）+ 如需平台主题资源则另出令牌 JSON
- 方向稿载体：**带平台原生边框的 mockup**（必须画出标题栏/菜单栏/系统控件）或**可运行的最小窗口壳**；**纯 HTML 页面截图不算桌面方向稿**——那会漏掉平台层
- 走查取证：**OS 级应用截图**（含真实窗口边框与系统控件，非浏览器内截图）+ **快捷键表逐条实操** + 平台 HIG 逐条核 + 辅助功能树检查
- 判据集：平台惯例遵从（按目标 OS 分列）· 快捷键覆盖完整且无冲突 · 窗口行为正确 · 原生辅助功能可读 · Web 判据集（作为子集沿用）
- **交付边界（v4.0.0）**：设计域只管**安装/更新的交互与可见性**（bootstrap 项）；**打包、代码签名、macOS 公证、自动更新通道、应用商店上架、内容分级/版号**归运维工程师（见其 skill §10 与 `契约/生产运维.md` §0.3「分发型交付物清单」）——设计与实现有人管，"做完了怎么发到用户手里"也得有人管

### 3.3 `game`（Unreal / Godot）

> **前置说明（v3.22.0 修正）**：本域原记为"无可借鉴的上游设计方法论"。**该结论只对"行为链"成立**（手感/玩法/关卡设计确实没有可复用的开源方法论）；**"美术资产链"有成熟上游标准**，本次已 clone 源码实读并实跑验证：
> - **资产命名/目录**：`Allar/ue5-style-guide`（MIT，★6.3k）—— 资产前缀/后缀表与目录规则是 UE 社区事实标准
> - **Art Bible 结构**：**0 A.D. Art Design Document** —— 唯一可直接抄章节骨架的开源实例（风格支柱 + 尺寸表 + 材质/光照预算）
> - **规格门禁**：**框架自建 `skills/UI设计师/scripts/art_lint.py`**（v3.22.0；ΔE00 公式经 Sharma 标准向量校验；无 Pillow 时降级）
> - **素材来源**：CC0 库（Kenney / Poly Haven / ambientCG，后两者有公开 API）
> - **可复现生成**：`pixel-art-studio` 的"build script = 唯一事实源 + validation.json 断言"（已实跑）
>
> **但仍须诚实标注**：Art Bible 的**章节模板**、**剪影测试的阈值**、**最终风格一致性签字**、**许可法务判断**在开源生态中**无实现**，只能写成清单靠人判断——**不得假装可全自动**（详见 `思路/01_调研.md` 的"可复用 vs 惯例"对照）。

### 美术资产链（v3.22.0 新增，五段）

> 为什么单列：原 game 域只有**行为**判据（手感/HUD/输入），缺**资产**判据 → 走查只能停在"我觉得不像"，**无法证伪**。本节把美术从"审美争论"变成"可复现的计数"。

| 段 | 必须设计与核对的内容 | 判据类型 |
|---|---|---|
| **① 美术方向** | **风格支柱**（3–5 条互相制衡的一句话，如"玩法优先于写实"）· **参考板**（分区：角色/环境/UI/特效；每张标注"**抄什么、不抄什么**"）· **色彩脚本**（按关卡/情绪推进的配色序列）· **材质与光照语言**（金属度/粗糙度语义、主光方向、色温、对比策略）· **剪影规则**（纯黑剪影下仍可辨识）· **尺寸与预算表**（texel density、poly/LOD 预算、图集上限） | 契约 · **人拍板**（方向由用户选，走【关卡③】） |
| **② 素材来源** | **逐资产标注来源**：自绘 / CC0 库 / AI 生成 / 外包。**CC0 优先**（Kenney、Poly Haven、ambientCG——后两者有公开 API）。AI 生成须固化 **ComfyUI workflow**（模型 hash + LoRA 权重 + seed + IP-Adapter 风格 + ControlNet 结构）并**生成后色彩归一**到美术令牌 | 台账 · 人核 |
| **③ 资产规格** | **命名**：前缀表按引擎分叉（蓝本 ue5-style-guide；Godot 文件/目录强制 `snake_case`、节点 `PascalCase`）· **贴图后缀**：`_D`/`_N`/`_R`/`_M`/`_O`/`_E`/`_A`，**通道打包按字母堆叠**（Emissive+Roughness+AO = `_ERO`）· **尺寸**：2 的幂、≤ 引擎上限、texel density 一致 · **格式与压缩**：Lossless（2D/像素画）/ VRAM Compressed（3D）分场景；**像素画必须 Point filter + 关 Mipmap** · **图集**：padding ≥ 4；**UI 图集必须关 Allow Rotation** · **预算**：如"每物体 1 UV + 1 Material"这类硬上限 | 契约 + **脚本门禁** |
| **④ 风格一致性** | **可机器证伪（硬门禁）**：**调色板覆盖率**（每资产主色到美术令牌最近色 **ΔE00 ≤ 阈值**，默认 5；覆盖率 ≥ 85%）· 命名/格式/尺寸/体积符合 spec · **alpha 渗色**（全透明像素不得残留 RGB）。**辅助手段**：截图回归（`pixelmatch` / `odiff` / Playwright `toHaveScreenshot`）· 色盲模拟下功能色仍可区分。**无成品工具**：剪影测试，需自写 OpenCV 脚本（列为可选） | **脚本（`art_lint.py`，error 即打回）** + 人做终判 |
| **⑤ 许可台账** | 每份外部素材记：**来源 URL · 作者 · 许可 SPDX · 获取日期 · 是否需署名 · 是否可再分发 · 修改说明 · 许可快照**。**必须记抓取当时的许可**——Quaternius 已从 CC0 改为自定义 QAL（典型"许可漂移"）。Freesound 的 `CC-BY-NC` **不可商用**。AI 素材记模型 + 版本 + 许可，并按平台要求披露。**字体默认白名单 = OFL**（`fonttools` 子集化） | 台账 · **人 + 法务判断** |

### 行为与系统链（原有）

| 维度 | 必须设计与核对的内容 |
|---|---|
| **手感（game feel）** | 输入→反馈的延迟预算 · 打击/命中的反馈层级（视觉+听觉+震动+停顿）· 镜头运动（跟随/阻尼/震屏及其可关闭）· 动画取消窗口与输入缓冲 |
| **输入映射** | 键鼠 / 手柄 / 触屏的映射表 · **按键重映射** · **提示图标随设备动态切换** · 死区与灵敏度 · 单手/无障碍替代方案 |
| **难度与节奏** | 难度曲线 · 检查点与容错（失败惩罚是否可调）· 新手引导（尽量非文字依赖）· 会话长度与中断恢复 |
| **HUD 与安全区** | 不同**宽高比矩阵**下不被裁切（16:9 / 16:10 / 21:9 / 4:3）· 字幕安全区 · UI 缩放选项 |
| **动态可读性** | 快速移动 + 特效 + 低对比背景下，关键信息（血量/弹药/目标）仍可辨识 · 色盲模式（不只换色，配形状/图标）· 特效强度可关闭（光敏友好） |
| **音频与反馈** | 关键事件的听觉提示 · 字幕与音量分轨 · 静音下信息不丢失 |
| **本地化** | 各语言文字长度膨胀对布局的影响 · 字形支持（CJK/阿拉伯语 RTL）· 配音 vs 字幕的时序 |
| **性能对设计的影响** | 帧率预算下的 UI 与特效取舍 · 加载与过场设计 · 低配档位的设计降级 |
| **数值与经济** | 若含成长/经济系统：产出-消耗闭环 · 数值膨胀与平衡 · 是否可被玩家解算（爆炸） |

- 导出目标：**引擎消费的资产/数据**——Unreal：DataTable / DataAsset + UMG 样式；Godot：`Theme` 资源（`.tres`）+ 常量表。**不导 Tailwind/CSS**（无效载荷）；**美术令牌另出一份 `UI资源/art-spec.json`**（供 `art_lint.py` 消费，色值按名引用 `DESIGN.md` 的 colors，**不复制**）
- 方向稿载体：**关键屏 mockup**（引擎内截图或矢量示意，近 1:1）+ **美术方向板**（见 `UI资源/美术方向板模板.md`：风格支柱/参考板/色彩脚本/材质光照语言/剪影规则/尺寸预算表）+ 可选一段**可跑的最小场景**；**用静态 HTML 稿表达不了手感与动效意图**——方向稿必须说明"动起来是什么感觉"
- 走查取证：**真机/编辑器内录像**（不是静态截图）+ 帧率与**输入延迟数据** + **玩测记录**（可完成率/卡点）+ **`art_lint.py` 输出**（含 `--json`，存 `证据/设计/art-lint.json`）
- 判据集：**WCAG 不适用**（静态对比度判据对动态游戏画面无意义）；替换为 **动态可读性**（录像抽帧核）· 输入响应是否达标 · 宽高比矩阵无裁切 · 教程可完成 · 关键信息在静音/色盲模式下不丢失 · **美术资产门禁 `art_lint.py` errors == 0**（命名/格式/尺寸/体积/调色板 ΔE00/alpha 渗色）· 素材许可台账无空缺字段

### 3.4 `mobile-native`（iOS / Android）

> 可借鉴最充分：Apple HIG、Material 3、SwiftUI / Compose 组件规范。

| 维度 | 必须设计与核对的内容 |
|---|---|
| **平台导航模式** | 返回栈与手势返回（iOS）/ 系统返回键（Android）· Tab 结构 · 模态呈现惯例差异 |
| **安全区与形态** | 刘海/灵动岛/挖孔 · 底部手势条 · 折叠屏与平板形态 |
| **平台控件与动效惯例** | 用平台原生控件与转场（不套 Web 观感）· 系统级动效语义 |
| **权限与隐私** | 权限请求时机与文案（先解释再请求）· 拒绝后的降级路径 |
| **弱网与离线** | 断网与慢网状态 · 本地缓存与同步冲突提示 |
| **通知** | 通知设计（时机/聚合/免打扰）· 应用图标角标 |
| **显示适配** | 深浅色 · **系统大字号（动态字体）下布局不破** · 触控目标尺寸下限 · 键盘弹出时的布局与输入类型 |
| **平台可访问性** | VoiceOver / TalkBack 可读 · 手势替代方案 · 对比度与动态字体（此域 WCAG 仍适用） |

- 导出目标：平台主题资源——iOS：Asset Catalog / SwiftUI 常量；Android：Material 3 theme XML / Compose
- 方向稿载体：**设备框 mockup**（含该平台的状态栏与导航栏，不用通用手机框糊弄）
- 走查取证：模拟器或真机截图（框架已有**内置安卓模拟器插件**纪律，见 agent.md 注意事项 17）+ 平台组件规范核对 + **动态字号与深色模式各出一张**
- 判据集：平台惯例遵从 · 安全区无遮挡 · 大字号不破 · 触控目标达标 · 权限与降级路径完整 · 平台可访问性可读

## 四、多域项目

同一项目跨多域时（如 Electron 桌面 + 移动端 + 后端）：

- **一份 DESIGN.md 令牌 + 每域一份"落地映射"**：令牌保持单一事实源，各域在本文档内声明自己的导出与适配差异，**不复制令牌**。
- **`EXPERIENCE.md` 按域分节**：导航模式、响应式/适配、可访问性底线按域分别写。
- **走查按域分别出结论**（同一卡若同时改动两域，走查记录分列）。
- 域间冲突（如桌面要密度、移动要触控目标）→ **显式记录取舍**，不静默取其一。

## 五、变更与豁免

- 域变更（如从 web 扩到 desktop）属**结构变更**：更新本文件 + `config.json` 的 `design_profile`，并**重新过【关卡③】**（新增域的适配需用户确认），记 `记忆/变更日志.md`（c-xxx）。
- **快速模式/A 档**：可豁免"3-6 个方向稿"与"两遍制走查"，但**域声明与判据集不得豁免**——至少按该域判据集做一遍自检并留证据；主控在项目计划注明依据。
- **`game` 域美术链的豁免边界（v3.22.0）**：①**美术方向**（风格支柱/参考板/色彩脚本）在 A 档可精简为"一句话支柱 + 参考板至少 1 张/分区"，但**不得空缺**——方向空缺则资产规格无据可依；②**素材许可台账（⑤）不得豁免**，任何外部素材必须登记（法务风险与档位无关）；③**④资产门禁 `art_lint.py` 不得豁免**（error 即打回）——它是本域唯一能机器证伪的资产判据，豁免它等于本域资产质量无判据。
- **令牌来源纪律（v3.22.0）**：`UI资源/art-spec.json` 的调色板**只列 `use_tokens` 引用哪些令牌名**，色值**从 `DESIGN.md` 的 colors 段按名解析**，**禁止在 art-spec 里复制色值**——否则改主题时两处不同步，门禁会拿旧色值放行。
- **美术色板放在 `colors` 段（v3.22.0 实测结论）**：美术色与 UI 色**同放 `DESIGN.md` 的 `colors`**。不要另立顶层组——实测 `artColors` 会触发官方 `token-like-ignored`，**export 命令会静默忽略它**，令牌传不到引擎侧。代价是"仅被资产引用"的美术色会被报 `orphaned-tokens` warning（`errors` 仍为 0，硬门禁不受影响），处置方式见 `skills/UI设计师/SKILL.md` §4.1.1 的**标准忽略决策**（作用域限定为 `art-spec.json` 的 `use_tokens` 列表，重触发条件 = 该列表变更）。**美术色用自己的名字**（`ink`/`gold`/`leaf`），不蹭 `primary`/`surface` 等规范色角色的豁免。
