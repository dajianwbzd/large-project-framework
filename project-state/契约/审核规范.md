# 审核规范（穿透审核：识别他人偷懒/幻觉/蒙混）

> 各角色的「常见借口表」是**自律**（防自己偷懒）；本规范是**他律**——审计/验收者用来**审其他角色的代码、思路文档、描述文件**，识别蒙混信号。审核记录落盘到 `project-state/问题/审核记录.md`。

## 一、蒙混信号库（识别特征 + 取证方法）

遇到以下任一特征，**不要放过**，按「取证方法」取证后判定：

| # | 信号 | 识别特征 | 取证方法 |
|---|------|---------|---------|
| S1 | **无证据断言** | "应该没问题""本地能跑""大概""先放着"，无命令/结果 | 要求真实命令输出到落盘文件；无则判**存疑**，打回取证 |
| S2 | **结论无来源** | 方案/结论无 URL/实验/代码证据，"我估计""应该" | 要求补来源；来源不明标"待核实"（违反防幻觉铁律） |
| S3 | **过于完美不像真的** | 思路文档只有①②③④、缺⑤⑥（结果与偏差）；产出全优无任何取舍/失败记录 | 查思路文档是否缺「结果与偏差」段；全优无料 = 可疑 |
| S4 | **不落盘** | "做了但没写报告""跳过""这个不重要跳过" | 查对应落盘位置（进度 json/代码/描述文件）；无产出 = 未完成 |
| S5 | **回滚/覆盖丢证据** | 关键修复/验证后未留 diff 或过程记录；改测试让用例过、删复现脚本 | 查提交前自审是否留档；验收用例是标尺，改测试 = 作弊 |
| S6 | **数据蒙混** | seed 与真实不符、mock 当真实、i18n/外键/状态码不符 | 落库核对 seed、切真实接口重验；禁止"mock 通了真接口崩" |
| S7 | **环境错位** | 用 dev 证据顶替 test 验收、跳过环境自检 | 要求 test 环境自检 + 证据三要素（环境+命令+结果）；禁止 dev 顶替 |
| S8 | **范围夹带** | 顺手改任务范围外代码 | 查 diff 是否含非任务文件；记入经验沉淀或 suggestion CR |

**通用取证四问**（对任何可疑产出先问，答案必须落到可核验文件）：
1. 你说完成了/没问题——**证据在哪**（落盘文件路径 + 命令输出）？
2. 这个结论怎么来的——**来源/依据**（URL/实验/代码证据）？
3. 这次到底跑了什么——**真实执行 vs 心理安慰**（是否重复跑同一命令、是否只看截图）？
4. 缺的东西是真的不重要，还是**你没做**？

## 二、三级判定与结论

| 判定 | 含义 | 对卡片处理 |
|------|------|-----------|
| **pass** | 证据充分，可追溯 | 不阻拦，进合并 |
| **存疑** | 证据不足以排除蒙混，需补充/修正 | 卡片退回 in_progress，附取证方法与修正要求 |
| **fail** | 证据缺失或发现造假 | 卡片回退 + 上报主控，记录在案 |

> **补充路径 —— 主动忽略决策（与三级判定并行，不替代）**：`契约/代码复查规则库.md` 的复查规则命中、但认定为不适用时，不是"放过"，而是走**忽略决策**——回答（是否误报 / 是否影响用户 / 是否列入 Backlog / 重新触发条件 / 谁拍板），落一条「忽略决策记录」到本文件（`问题/审核记录.md`）并同步 `记忆/决策日志.md`（d-xxx）。**"会影响用户"或"不列入任何后续"的忽略不成立**，必须修复或转 CR。无忽略决策记录 = 未处理（视同 S4 不落盘）。此路径让"检查过但决定不办"这件事有据可查，与三级判定共同构成完整验收。

## 三、结论可追溯性（写作纪律）

- 审核记录必须**引用具体落盘文件路径 + 复现命令 + 客观结果**，禁用"整体看没问题""应该还好"。
- 只认工作区证据；"角色自己说完成了"不作为可追溯依据。
- 每条结论都到"能指出对应落盘文件"为止——**没有落盘 = 没干，审核也是**。

## 四、审核记录模板

写入 `project-state/问题/审核记录.md`（追加；每卡一条）：

```markdown
# 审核记录：<card-xxx>（<审核角色>）

## 结论
- 判定：pass / 存疑 / fail
- 卡状态：保持 done / 退回 in_progress

## 被审核产出
| 产出 | 位置 | 审核动作 |
|---|---|---|
| 代码 | project-state/代码/<角色>/… | <核对方式> |
| 思路文档 | `需求卡/card-NNN/思路-<角色>.md`、`测试卡/tc-NNN/思路-<角色>.md`（跨卡主题才在 `思路/<角色>/通用-<主题>.md`） | 查 ①~⑥ 是否完整 |
| 描述/进度文件 | project-state/进度/<角色>.json | 查 deliverables 是否引用落盘 |
| 卡级验收记录 | `需求卡/card-NNN/验收-<路>.md` | 查逐条依据 + 证据指针齐全（缺 = 该路验收未达标，打回补齐） |

## 蒙混信号检查（对照信号库）
| 信号 | 命中(是/否) | 证据 | 取证方法 | 结论 |
|---|---|---|---|---|
| S1 无证据断言 | … | … | … | … |

## 可追溯依据
- 证据文件：<路径>（命令：<命令> → <结果>）
- 来源：<URL/实验/代码证据>
```

## 五、用在哪
- **审计/验收角色（安全审计/集成）**：验收 done 卡时，除本职维度外，按本规范对**其他角色产出**（代码+思路文档+描述文件）做穿透审核，把「审核记录」作为报告前置。
- **测试工程师**：做**黑盒功能验收**（像用户一样操作验证，见其 skill），**不做他律/穿透审核**——避免与前后端职责重叠、减少额外负担；结果向上汇报。
- **项目经理**：验收合并前核对各路报告的「审核记录」齐全（含 UI 面卡的设计走查一路）；合并时做他律核查。
- **UI设计师（设计走查，v3.19.0）**：走查 `ui: true` 卡时按本规范的取证纪律执行——**S1 无证据断言同样适用**（"我看代码应该对"不算结论，必须真实运行界面截图）；走查结论落 `需求卡/card-NNN/验收-设计.md`；**走查不改业务代码**（修复归前端），也不对非界面维度（功能/契约/安全）下结论，避免与其他验收路重叠。
- **主控**：阶段 5 验收前置检查加「审核记录存在且非空壳」。
- **测试卡轮（v3.17.0）**：系统级测试卡收口前，核 `测试卡/tc-NNN/覆盖矩阵.md`（每条维度有无证据）与 `发现项.md`（**有无"无归属"项**）；发现项出现"待定"即打回补归属，不代劳。
