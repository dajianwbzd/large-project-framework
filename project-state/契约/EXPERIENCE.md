# 体验契约（EXPERIENCE.md）— 怎么运作

> UI设计师产出。**与 `DESIGN.md` 对等的第二份契约**：`DESIGN.md` 管「长什么样」（视觉令牌与外观），本文件管「怎么运作」（结构、行为、状态、旅程）。
> 两份契约冲突时**以契约为准**——任何 mock、稿子、导入件都不推翻契约。
> **拉取而非复制**：上游内容（PRD 段落、人物、需求名）**按名引用**，不粘原文，避免两处真相。
> **L0 摘要**：本产品的信息架构、行为规格、状态模式、可访问性底线与关键旅程。
> **可验收条款（v5.17.0）**：每节末尾的 `ux-clause` 表是本节承诺的**可判形态**——体验门（`scripts/ux_gate/`）只认这些条款 id，判不了的东西不进表（见文末「门禁条款强制说明」）。

## Accessibility Floor（可访问性底线 —— **实现方式随域变**）

> 视觉部分（对比度数值）在 `DESIGN.md`；本节管**行为**。**实现方式按域换**（`契约/设计域.md`）：
> - `web` / `mobile-native` → WCAG 2.1 AA + 平台可访问性（VoiceOver/TalkBack）；用 `aria-*`
> - `desktop` → **平台 HIG + 原生辅助功能 API（Windows UIA / macOS AX）——`aria-*` 不是唯一手段**；含**快捷键覆盖**（无鼠标可完成主流程）
> - `game` → **动态可读性**（快速移动+特效下关键信息可辨）+ 色盲模式（配形状/图标而非只换色）+ 特效强度可关闭（光敏友好）+ 静音时信息不丢失 + **按键重映射**

- [ ] 全流程键盘可达（Tab 顺序合理、无键盘陷阱、可见焦点样式一律 `{colors.focus}`）
- [ ] 无可见文本的图标按钮均有 `aria-label`（**逐条列出文案**）
- [ ] 表单：`label` 与字段关联；错误文本 `aria-describedby` 关联；错误可被读屏读出
- [ ] 浮层：`role=dialog` + `aria-modal` + `aria-labelledby`；焦点管理见 Component Patterns
- [ ] 颜色不是唯一信息载体（状态除颜色外有文字或图标）
- [ ] 动效尊重 `prefers-reduced-motion`
- [ ] 图片替代文本策略（装饰性图 `alt=""`）

## 体验门禁映射（UX Gate Mapping，v5.17.0）

> 上面每节的条款是**判据**；本节说明**谁来判、怎么判、判到哪一档**。四层越往下越贵，能上游拦的不要拖到下游。

### 四层门禁

| 层 | 做什么 | 成本 | 覆盖 | 工具 | 结论措辞 |
|---|---|---|---|---|---|
| **L1 静态** | 不启动应用：CSS/HTML/DOM 结构、aria、`flex-wrap` 继承、写死计数、键位表冲突、栅格定义唯一、反例标记 | 毫秒级（必须 <1s） | 继承冲突类 / 结构可判类 | `ux_gate/static_check.py` | "结构性体验未见违例" |
| **L2 运行时断言** | 起应用 + CDP **相对断言**（视口内/命中/可点/持久化/几何一致/iframe 高/键位跨帧/状态可渲染） | 秒级（单页 <10s） | 结构性体验 | `ux_gate/runtime_assert.py` | "结构性体验未见违例" |
| **L3 像素基线** | 固定取样条件（尺寸/DPR/主题/字体/关动画）→ pixelmatch（`threshold=0.1` 忽略 AA）+ `maxDiffPixelRatio <= 0.01` | 秒级 | 塌陷/遮挡/溢出/错位（**不做审美评分**） | `ux_gate/runtime_assert.py --baseline` | "改动页像素无漂移" |
| **L4 隔离评审** | 判断类：只在渲染件上逐条判断（入口位置/信息层级/一致性/审美），结论落账本 | 分钟级 | 判断类条款 | UI设计师 Pass 2' | 逐条 `strong / adequate / thin / broken` + 依据 |

### 档位映射（跟既有 `test_depth` 对齐，**不新造概念**）

| 档位 | UX 门下限 | 允许的结论措辞 |
|---|---|---|
| `smoke` | L1 全跑 + L2 只跑"窗口 / 导航 / 状态"三组；L3 不出基线 | **只能写"冒烟未见异常"**，不得写"通过" |
| `targeted` | L1 全跑 + L2 跑受影响模块 + L3 只比改动页 | 可写"受影响面未见违例"，范围必须点名 |
| `full` | L1 + L2 全跑 + L3 全量基线 + L4 判断类走查 | 可写"按档通过"，并列出 skipped 项与原因 |
| 交付包 / 上线前 | **必须 `full`**；体验包可 smoke/targeted，但包内必须写"哪些面未独立验证" | 沿用既有交付口径 |

### 账本（机读块 `machine:ux`，一行一条）

写在测试卡 / 交付记录的正文里（围栏 `<!-- machine:ux -->` … `<!-- /machine:ux -->`），列固定为：

`id | at | card_or_tc | clauses | level | verdict | evidence | note`

- `id`：`UXR-NNN`，全局唯一升序；`at`：`YYYY-MM-DD HH:MM`；`card_or_tc`：`card-NNN` / `tc-NNN`
- `clauses`：逗号分隔的**本文件条款 id**（必须能在本文件找到，否则 = 契约缺口 → 提 CR 回填，不许现场编）
- `level`：`smoke` / `targeted` / `full`（本行代表的档位）
- `verdict`：`pass` / `fail` / `skipped`（非空；`skipped` 必须在 `note` 写原因）
- `evidence`：项目根相对路径（脚本 JSON / 截图 / 基线 diff），**"客户看了说好"不属于 evidence**
- `note`：一句话结论或跳过原因

### 措辞纪律（与"冒烟 ≠ 通过"同构）

1. L3 像素通过 ≠ 体验良好；L1/L2 通过只能写 **"结构性体验未见违例"**。
2. `skipped` 必须写原因，**不许留空**（留空 = 未收口，`framework_lint.py` U 组判 ERROR）。
3. **只有 `full` 档的行才允许 `pass`**——`smoke`/`targeted` 行的 `pass` 视为越级结论（U 组判 ERROR）。
4. 清单每条必须回指条款 id；**对不上 = 契约缺口**（提 CR 回填本文件），不许凭感觉加判据。

## 门禁条款强制说明（Mandatory，v5.17.0）

1. **可判才准进表**：本文件每节的 `ux-clause` 表只收**有 id、有判据、有层**的条款；判不出来的东西写进 `Open Questions`，**不许伪造成条款**（伪条款会在验收时变成"没法判 = 没人管"）。
