## 风格基调（v4.2.0，含界面的项目必填）

> **产品经理产出、UI设计师 消费**。只写**产品侧主张**，不写视觉实现（色值/组件/排版归 `契约/DESIGN.md`）。
> 它是**风格确认关口**（④ 构建执行前的内部关口，v4.2.0）的判据来源：UI设计师 出的方向稿要逐条对得上本节，产品经理据此**确认 / 退回**（退回须指明哪条不满足）。

| 项 | 内容 |
|---|---|
| 服务定位与人群 | <这套界面为谁、在什么场景用；产品差异化在哪> |
| 情绪与调性（3–5 条，可判定） | <如"克制专业、不炫技"／"轻松但不幼稚"／"信息密度高但可读"> |
| 必须体现 | <如"数据优先、层级分明"> |
| **明确不要**（负向约束） | <如"不要玻璃拟态／不要大面积渐变／不要玩具感"> |
| 与竞品 / 现有系统的关系 | <延续 or 区隔，区隔在哪一点上> |

**可判定要求**：每条调性主张都要能被某版方向稿"证伪"（产品经理说得出"这版哪里不符合"）；写不出反例的主张视为不合格（对齐 `完成定义.md` 的可验证精神）。**纯审美偏好不属本节**，落 `EXPERIENCE.md` 或走建议项。
