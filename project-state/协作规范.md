# 协作规范 — 角色产出落盘与共享工作区纪律

> 版本：v5.1.0（随大型项目开发框架 v5.1.0 模板复制到项目；v3.17.0 卡卷宗、v3.18.0 六域路径模型、v3.22.0 工程治理五件套、v3.23.0 提示词与性能责任面、v4.0.0 安全与数据 / 客户端交付 / 单元测试责任面、v4.1.0 快速模式临时兼岗、v4.2.0 产品经理风格基调确认、v4.3.0 用户澄清与需求确认、v4.4.0 项目经理工作区整洁收口、**v4.5.0 验收前置检查改指针 + 项目经理长时任务估算**、**v5.0.0 指导模式、v5.1.0 覆盖面声明与 G11 自增强回路**继续有效）
> 本文件是「大型项目开发框架」的落地补充：**每个角色的产出必须以文件形式体现在 project-state/，共享工作区是角色间唯一交互通道。** 项目可在此文件基础上补充项目特定约定（如代码落盘位置、环境说明）。

## 1. 角色独立 AI 上岗机制（v3.8.0 子代理派发）

- 主控（指挥官，v3.9.0：组队/派活/调度/汇报；项目经理只是其"汇报/合并臂"之一，非主控本身）按任务加载对应角色：读 `skills/<角色>/SKILL.md` 后以该角色身份独立工作（大块任务按 v3.8.0 机制派发独立子代理执行）
- **一个任务 = 一个角色 AI 独立完成**，产出落盘后才由主控路由给下一角色；角色之间不直接对话，只读写共享工作区
- **子代理派发（v3.8.0）**：启用角色领卡**一律派发**独立子代理执行（不内联包办），**内联仅限 ≤1 文件且 ≤数行**的极小改动；**>3 文件 / 50 行净增必须派发**——主控只维护卡片状态机与路径指针，派发前封装简报（卡片 + 契约指针 + 记忆指针 + 落盘位置 + DoD），子代理只读简报指向内容；**退出报告三要素（改了什么/证据/落盘路径）缺失 → 打回重做**；验收子代理独立于开发派发（创建者 ≠ 验证者）；共享记忆区只追加不回改（子代理写独立文件，主控合并）
- 主控负责：派活、路由 CR、检查落盘质量（验收前先查工作区，不信任口头/印象结论）

## 2. 每角色产出落盘要求（硬性）

每次角色工作结束，必须留下以下产出（能写全就写全）：

| 产出类型 | 位置 | 内容 |
|---|---|---|
| **思路文档（v3.7.0；v3.17.0 卡卷宗）** | **卡内**：`需求卡/card-NNN/思路-<角色>.md`、`测试卡/tc-NNN/思路-<角色>.md`；**跨卡**：`思路/<角色>/通用-<主题>.md`/`盘点-<主题>.md` | 顶部加 `> L0 摘要：…`（一句话"怎么想、为什么"）；开工先写 ①任务定位 ②现状事实 ③方案与取舍 ④实施计划，完成/阻塞补 ⑤执行记录 ⑥结果与偏差（模板：`思路/思路文档模板.md`；一卡一角色一份） |
| **角色记忆档案（v3.8.1，v3.12.0 补 L0/L1/L2）** | `记忆/角色/<角色>.md` | 本角色跨卡长期沉淀：①本项目固定约定 ②踩坑记录 ③实现风格 ④待办/遗留；**派发前必读（先 L0 摘要判相关、L1 掌握要点）、收工必写（先自提炼再追加）**，经验三级升格：卡 → 档案 → `记忆/知识沉淀.md`（k-xxx） |
| 进度文件 | `进度/<角色>.json` | role / status / updated / summary / deliverables / cards / open_issues / notes，工作结束即更新 |
| **卡级验收记录（v3.17.0；v3.19.0 加设计一路）** | `需求卡/card-NNN/验收-<路>.md`（测试/集成/安全各独占一文件；**`验收-设计.md` 仅 `ui: true` 卡**）+ 证据 `需求卡/card-NNN/证据/<角色>/`（设计走查证据在 `证据/设计/`） | 本卡某路验收判定 + 逐条依据 + 证据指针；一卡一路一份、只写自己那份；**设计一路由 UI设计师 在真实运行界面走查产出（非前端自评，守创建者≠验证者）**；系统级测试轮写 `测试卡/tc-NNN/覆盖矩阵.md` + `发现项.md` |
| 描述性文件 | `代码/<角色>/开发说明.md`（**仅开发类角色：前端/后端/测试/运维/数据工程师**） | 代码位置与构建、按需求卡做了什么（表：需求卡｜做了什么｜关键文件｜验证证据）、open 缺陷/待办、遗留事项；**分析/设计/产品/管理类角色不在 `代码/` 建目录，落点见各自登记域**（`agent.md`「统一路径管理」，如代码解析师→`记忆/调研/代码分析/`、UI设计师→`契约/UI资源/`） |
| 契约/记忆 | `契约/`、`记忆/` | 涉及契约变更或关键决策时同步更新（c-xxx / d-xxx） |
| **对外交付件（v3.18.0；v4.4.0 加收口）** | `交付/`（客户交互区） | 会被发给客户/甲方看的最终件：交付包/发布包/方案书/报价单/进度报告/系统交付报告/验收单；内部构建件留 `产物/`；发出时登记 `交付/发出记录.md`（**永不清理**）。**顶层判据（v4.4.0）**：当前有效件 + `发出记录.md` + `归档/`——旧版本移 `归档/`、中间物进 `tmp/` |

规则：

1. **没有落盘 = 没干**：角色工作结束后若工作区无任何新产出，视为未完成，打回补齐
2. **思路先行（v3.7.0）**：先落思路文档 ①~④ 再动手；done 卡无对应思路文档，主控验收打回；测试/安全/集成/代码解析等角色的审查思路与结论同样落纸面（各角色差异化要求见模板附表）
3. **角色记忆必读必写（v3.8.1；v3.12.0 补 L0/L1/L2）**：子代理开工必读本角色档案 `记忆/角色/<角色>.md`（继承本项目约定/踩坑/风格）——**先读档案 L0 摘要判相关性，L1 概述掌握约定/踩坑，仅在需要细节时读 L2**（见 `契约/上下文规范.md`）；收工**先跑自提炼**（本卡新产生的约定/踩坑/风格/用户偏好，写成 L0+L1）再追加进档案（只追加不回改），值得长期复用升格 `记忆/知识沉淀.md`；档案缺字段可由主控补建骨架，不阻塞开发
4. **证据而非感觉**：描述性文件里写验证证据（环境 + 命令 + 结果），"应该没问题"不算数
5. **代码位置声明**：代码真实落盘位置不在工作区 `代码/<角色>/` 时（如独立 repos/），描述文件写清实际位置；工作区放描述性文件与关键产物（APK/SQL/脚本/证据索引），不复制源码双份
6. **卡片同步（v3.17.0 卡卷宗）**：状态变更（todo/in_progress/reviewing/done/blocked）同步到卡本体 frontmatter（`需求卡/card-NNN/card.md`、`测试卡/tc-NNN/tc.md`）；卡片「进展记录」引用思路文档路径；**测试卡发现项按三选一归属处置**（A 回退需求卡 / B 新建修复卡 / C CR 或忽略决策），无归属 = 未收口
7. **设计走查不走思路文档（v3.19.0）**：`ui: true` 卡的设计还原走查结论落 `需求卡/card-NNN/验收-设计.md`（**不是** `思路-UI设计师.md`）——思路文档记"怎么想"，验收-设计记"核完的结论与证据"；同一角色在同卡可以两者都有（既参与设计又走查），互不替代
8. **临时兼岗标注（v4.1.0）**：快速模式/按需组队下，未启用角色的工作由主控**临时分发给已启用角色或内联**承接（映射表与"必须升级"条件见 `agent.md` 运行模式要点 10）。**产出落盘必须标注「临时兼岗 + 实际承接者 + 判据来源」**——不得署名原属角色、不得记成"该角色已验收"；只兼**有既有判据的轻活**（跑脚本/按清单自查/写单测/许可 grep/性能实测命令；**现场自定标准 = 自出题自判分，禁止**）；兼岗者为实现方时**不得自判验收通过**，否则显式标注"未独立验证"并计入风险；命中"必须升级"条件（认证/敏感数据/对外交付/生产/客户端交付/迁移/多模块）即启用该角色或切完整模式。**兼岗不是降标准**
9. **风格基调与确认落盘（v4.2.0）**：含界面的项目，产品经理的「风格基调」§ 落 `契约/产品需求文档.md`（含"明确不要"）；对方向稿的**确认/退回结论 + 逐条依据**落 `需求卡/card-NNN/风格确认-产品经理.md`（**④ 前内部关口，不是验收路**——四路验收口径不变）。产品经理**不产出/不改写方向稿、不审美术质量、不改判设计走查 fail**；僵持走 CR
10. **用户澄清与需求确认落盘（v4.3.0）**：产品经理与用户的**贯穿式澄清循环**（主控开窗调度、产品经理主持；每轮 ≤5 问附候选、**答案写回** PRD/卡）产出 `需求卡/card-NNN/需求确认-产品经理.md`（**带版本 + 日期**）：理解确认单（用户逐条确认/修正 + 原话要点）· 关键假设（已确认 / 按授权默认）· 待澄清清单（**应为空**）· 授权留痕（范围/时间/授权人）。**未澄清项就地标 `[待澄清: 问题 + 候选选项]`、"猜的"标 `[假设]` 并单列**；卡 frontmatter `clarify_open`（>0 = 未就绪）与 `req_confirm` 指向确认物。**`[待澄清]`=0 且假设已确认才可下发开发**；**需求变更 = 旧确认作废、升版本重新确认**，不得单方改卡，**旧版留档不删除**（`归档/需求确认-v<N>.md`），卡 `req_confirm` 同步指向新版；用户未及时答 → 交主控进 `待办/自然人.md`、卡置 `blocked`，不自行拍板
11. **工作区整洁与清收（v4.4.0，项目经理常设职责）**：工作区与各域目录保持干净、**每次工作完成时整理一遍**、中间文件与一次性脚本即清、**给客户的交付文件及时收口**。五类时点：①**本角色每次工作收尾**（项目经理每次交出报告前）②批次收口 ③里程碑收口 ④交付发出后 / SHIP 前 ⑤用户随时要求——跑 `python scripts/workspace_hygiene.py <项目根>`（**默认只报告 dry-run**），结论写 `运行日志.md` + `进度/overall.json` 的 `hygiene` 段。**分级授权**：L1 垃圾 / 超龄 tmp / 散落一次性中间件 / 交付中间物**可自动删**；产物与交付旧版**归档**（`产物/归档/`、`交付/归档/<日期>/`）；`*.log` **只报告**（可能是唯一故障线索）；**已发出副本永不自动删**（不可逆对外动作，须列清单含文件/版本/哈希/发给谁/回执，报主控/用户确认）。**硬保护**：卡卷宗与测试卡 `证据/`、`交付/发出记录.md`、`project-state/` 正式产出、`.git/`。**归位不是清理**：根级散落脚本/文档的归位与结构变更走 `path_audit.py` + 主控裁决；无法判定归属的游离物**不删**，登记 `待办/自然人.md`。**各执行角色收工即清本卡 tmp 产物**（不清 = 未完成收工），项目经理负责批次统一收口——**"交付完"≠"活干完"**。

## 3. 共享工作区是唯一交互通道

- 角色间不私聊、不留私有笔记；一切信息通过 project-state/ 传递
- 跨角色发现的问题 → `问题/<角色>问题/cr-NNN.md`（CR 机制），主控负责路由
- 关键决策 → `记忆/决策日志.md`（d-xxx）；契约变更 → `记忆/变更日志.md`（c-xxx）；技术沉淀 → `记忆/知识沉淀.md`（k-xxx）
- 开工前读工作区：读需求卡「相关记忆」+ 最新 `契约/`，防止基于过期信息开发

## 5. 中途接管 / 续接项目

接手已有项目时，主控先做工作区完整性盘点：各角色 json 缺的建骨架、描述文件缺的补齐、依据任务清单/overall.json/记忆回填历史产出，并向用户说明哪些是回填、哪些是真缺；盘点结果写入 `进度/项目经理.json` 作为验收基线。**v4.4.0 起盘点同时跑整洁收口**：`workspace_hygiene.py` 出分级清单（垃圾/超龄 tmp/散落中间件/旧版本/交付件），清理项由项目经理执行、归位与结构变更由主控裁决——**接管的老工作区往往是脏乱重灾区，先清出"能信的基线"再谈验收**。

## 6. 上下文工程（v3.12.0，借鉴 OpenViking）

所有角色读上下文（记忆/契约/思路/进度/需求卡）遵守 `契约/上下文规范.md`，核心三条：

1. **先判相关性再定深度（L0/L1/L2）**：读上下文先读 `契约/上下文索引.md`（L0 摘要定位），命中子目录后按 L0（摘要≈100t）→ L1（概述≈2k）→ L2（详情按需）逐层下钻；**禁平铺全量**（把 `记忆/`、`契约/`、`思路/` 全读完再筛）。
2. **重要检索留轨迹**：检索"读了哪、为何采用"写进卡片「进展记录」/思路文档 ② 段，供 `契约/审核规范.md` S1 取证——检索结论可证伪、可追溯（对齐"证据而非感觉"）。
3. **收工先提炼再落盘（会话自提炼）**：done 卡收工先跑自提炼三问（①用户偏好/新约束 ②本角色可复用模式/新踩坑 ③是否升格），写成 L0+L1 落 `记忆/决策日志.md`(d-)/`记忆/知识沉淀.md`(k-)/`记忆/角色/<角色>.md` 追加记录；未提炼 = 未完成沉淀（同"没有落盘 = 没干"）。

> 三层分级（L0/L1/L2 内容深度）与既有「加载优先级（高/中/低）」正交：优先级回答"该不该读"，深度回答"读到多深"。上下文索引 L0 由主控按 agent-managed storage 规则统一维护。
