### 变更矩阵机读块（v5.24.0，`变更矩阵.md` 里必须有；本卡涉及变更语义时才需要）

> **为什么有这一段**：覆盖维度 ⑫「变更后一致性」管的是**给出去又收回之后，东西还对不对**——形态固定四段 `给权限/给归属 → 做动作 → 收回 → 问产物对不对`（例：把 A 绑上高级管理员 → A 生成审批单 → 取消 A 的角色 → 问 A 还能不能看到这张单）。它**不是**既有 ⑤（静态角色矩阵）与 ⑥（同一实体的状态机）能兜住的：⑤ 只查"这个角色能不能进"，⑥ 只查"这个实体自己转态对不对"，**"回收之后原来产出的东西该不该还看得见"是两者的夹角，此前没有任何维度管它**。
> **什么时候必须有**：本卡覆盖的需求卡涉及**权限、归属、时效、派生数据**任一项，且存在"先给了又收回 / 换过人 / 会到期 / 要重算"的语义时。**判据不在契约里就不许自己编期望值**（那是替产品做决策）：先要求产品经理补 PRD「变更语义」三问（生效时点／回收后哪些面还可见／在途数据归谁），补不上就提 CR。
> **放在** `测试卡/tc-NNN/变更矩阵.md`。人读表照旧写；机器只读下面这个围栏块。
>
> - `id` = `MU-NNN`（**三位数字，全局唯一升序**，只增不改）
> - `object` = 被变更的对象（表名/实体名，如 `approval_order`）
> - `event` = **变更事件，四子族取一**：`权限与角色回收` / `归属与组织变更` / `时效到期` / `派生数据重算`
> - `faces` = 可见面，七面取子集、逗号分隔：`列表` / `详情` / `直达链接` / `导出` / `搜索` / `通知` / `统计`；整行不适用写 `na`；全七面写 `all`
> - `cas` = 对应的用例号 `CAS-NNN`（**必须在 `代码/测试/用例库.md` 里真实存在**）；`covered`/`partial` 必填，`na`/`accepted` 可写 `-`
> - `result ∈ covered|partial|na|accepted|unknown`——**`unknown` = 未回填，不许写成 `covered`**；`na` / `accepted` **必须写 `reason`**
> - `reason` = 为什么 `na` / `accepted`，或 `unknown` 的原因；**必填，不许空着糊过去**
> - **`|` 是列分隔符，字段内不许出现**——需要写多个用 `,` 或 `/`
> - 机检 `python -X utf8 scripts/mutation_coverage_audit.py <项目根>`：**0 干净 / 1 有 ERROR / 2 无法检查**——**2 不是"没问题"**

> - **`entry` = 怎么复现**（v5.7.0 新增）：一条可复跑的命令 / 触发路径 / 最小用例。
> - **`anchor` 与 `entry` 不得同时为空**：`anchor` 可以是「未知」，那时 `entry` 必填。
>   写发现项的人**当时就在那一处**，这两格对他几乎零成本；丢了它，下一个接手的人要**重新定位一遍**。
> - **`|` 是列分隔符，字段内不许出现**——需要写多个用 `,` 或 `/`。
> - **旧版 5 列块**（无 `anchor`/`entry`）会被 `recall.py` 报一次
>   `TC-FINDINGS-FORMAT-STALE`（**格式旧**，不是内容缺）——把两列**追加到行尾**即可，旧行内容不用动。

> **取用—归还块（v5.11.0）**：**7 列一个字都不能差**（`scripts/browser_resource_audit.py` 逐字匹配列头）；`BRW-NNN` 全局唯一、升序、只增不改；**「开」（`take`）与「关」（`return`）写在同一行**——`return` 空 = 取用未归还（`BRW-NO-RETURN`）；`tabs` ≤ 卡上 `browser_tab_cap`（超了 `BRW-TABS-OVER`）；跨卡独占时段重叠（`BRW-OVERLAP`）、`session` 空、证据指针悬空、`BRW-NNN` 重复或乱序都会报 ERROR；时间只认 `YYYY-MM-DD HH:MM` / `YYYY-MM-DDTHH:MM`；`|` 是列分隔符，字段内不许出现。**没用到浏览器取证的本卡可整块省略**（正文出现"浏览器 / BrowserSkill / browser_ / bsk "任一词却缺此块 → `BRW-MISSING-BLOCK`）。
