## 原型锚点（`ui: true` 卡且完整模式必填，v5.15.0）

> **为什么有这一节**：文字卡能让 AI 实现，但**让用户"点一遍"才知道流程对不对**——屏集漏一屏、跳转少一步，等到实现完才发现，返工的是前端 + 测试 + 走查三条线。产品经理在卡上把「长什么样、走哪条主线」钉死，下游（UI 设计师取屏集与流转为基线、前端照流程实现、测试照流程写用例）就不用各自猜。
> **指针纪律**：原型是**项目级资产**（`契约/UI资源/prototypes/`），卡上只留指针与结论，**不把 HTML 复制进卡卷宗**。`ui: false` 的卡本节填 `-`。

| 项 | 值 |
|---|---|
| 原型 spec（**唯一事实源**） | `契约/UI资源/prototypes/prototype.spec.json` |
| 渲染件 | `契约/UI资源/prototypes/prototype.html`（`scripts/render_proto.py` 产物，**禁手写**；sha256 `<值>`） |
| 屏与 REQ | S1 `<屏名>`（REQ-x.y）· S2 … |
| 主流程 | `<S1 → S2 → S3 …>`；流程图 `shots/flow.png` |
| 截图 | `契约/UI资源/prototypes/shots/`（375 / 1440）+ `manifest.json`（记 `htmlSha256`） |
| 门禁 | `python -X utf8 scripts/prototype_lint.py --spec … --html … --shots …` → **0 error** |
| 用户点过 | 是 / 否 + 日期 + 结论（哪几屏被要求改，改后重出图） |
| 快速模式 | 做 / 跳过（**跳过须在此留一行理由**，否则视为漏做） |
