# 用例库模板

> 测试工程师维护 ｜ **一项目一份** ｜ 落点：`project-state/代码/测试/用例库.md`（v5.8.0 起**用例资产的唯一落点**）
> **为什么要它**：`测试卡/tc-NNN/覆盖矩阵.md` 回答「**这一轮**覆盖了哪些维度」；本文件回答「**这个项目一共攒下哪些用例、每条的判据是什么、最近一次跑成什么样**」。
> 没有它，每轮开工都要重新想一遍用例——要么每轮一样（漏新风险），要么每轮全新（烧 token 且丢掉上轮判据），**两头都亏**。
> 机器只读下面的 `<!-- machine:cases -->` 围栏块；检查器：`python scripts/case_audit.py <项目根>`（0 ERROR 才算登记完成）。

## 1. 三条纪律（先读这一段）

- **固定回归基线 + 失败驱动增量**：每轮先跑基线用例（`source` = `AC:` / `回归:`），再按**发现项**（`发现:`）、**用户反馈**（`反馈:`）、**探索**（`探索:`）**新增**用例。
  **禁止「每轮全新用例」**（等于把上轮判据扔了）；也**禁止「每轮原样重复」**（等于不测新风险）。
- **只增不删**：`id` 全局唯一、只增不减、**永不复用**；用例作废改 `last=retired`（**行保留**）。删行就看不出「曾经测过什么、为什么废」。
- **反 mock 判据必填**：`anti_mock` 留空、`-`、`无`、`n/a` 会被检查器**直接报 ERROR**。
  一条用例若只断言「我想要的响应出现了」，**不证明它真来自系统**——前端 mock 层、伪造响应、缓存、假接口都能让它通过。
- **哨兵纪律（v5.28.0）**：**修过的 bug 必须留哨兵**——每个修复（修复卡）在用例库有一条能复现该 bug 的 CAS（`source` 按来源写 `发现:`/`反馈:`/`探索:`），修复后跑出 `last=pass` 并回填，卡上 `reg_case` 指向它；**哨兵 `last=fail` = 旧 bug 复现（二进宫）** = 当轮最高优先级：建修复卡 `source: 回归:CAS-NNN`，写清归因「哪个后续改动把它弄坏的」，修好后**复用同一条 CAS** 把 `last` 翻回 `pass`——不新造行。机检：`python -X utf8 scripts/regression_audit.py <项目根>`（**退出码 2 = 无法检查 ≠ 没问题**；`--impact <路径|card-NNN>` 列同文件历史发现项与碰撞哨兵——修 B 前先看 A 的哨兵）。

## 2. 人读表（照旧写，给人看）

| CAS | 范围 | 设计方法 | 数据 | 反 mock 判据 | 来源 | 最近一次 |
|-----|------|---------|------|--------------|------|---------|
| CAS-001 | card-001 | 等价类+边界值 | 金额 0/1/上限/上限+1 | 直查库核余额 + 越权应 403 | AC:REQ-1.1 | pass |

> 人读表与机读块**一次写成两处**，别事后回头补（同 `测试卡模板.md` v5.7.0 的做法）。

## 3. 机读块（必须有）

```text
<!-- machine:cases -->
id | scope | method | data | anti_mock | source | last
CAS-001 | card-001 | 等价类+边界值 | 金额 0/1/上限/上限+1，seed 42 | 写入后换连接直查库核余额；越权用另一账号复读应 403 | AC:REQ-1.1 | pass
CAS-002 | tc-001 | 状态迁移+穿透 | 状态机 5 态各走一次，非法转换 3 条 | 库内状态字段直查 + 拦截器日志留痕 | 发现:tc-001#F-01 | unknown
<!-- /machine:cases -->
```

列义（**7 列，顺序固定**）：

- `id` = `CAS-NNN`（**全局唯一、只增不减、永不复用**；格式 `CAS-` + 3 位数字）
- `scope` = `card-NNN` ｜ `tc-NNN` ｜ `global`（**写了就必须真实存在**——指向不存在的卡/轮会被报悬空）
- `method` = 设计方法（可 `+` 组合）：`等价类`／`边界值`／`判定表`／`状态迁移`／`正交`／`场景法`／`错误推测`／`变异`／`穿透`
  （只用这九种名字；写别的名字会被报「未知方法」。**这一列是给自己看的**：逼你想清「这条用例是按什么方法设计出来的」，而不是随手点两下）
- `data` = 数据怎么来（夹具／seed／库快照／造数脚本），**必须可复跑**——写「随便造几条」等于没法复现
- `anti_mock` = **反 mock 判据**（四类任选或组合）：
  ①**独立通道复核**：换个通道复读同一事实（界面写的数 ↔ 直查库／再调一次只读接口）
  ②**负向证据**：越权/非法状态**必须被拒**（只测「能成功」测不出假的成功）
  ③**环境指纹**：把库名/版本/seed 哈希记下来，与响应里的指纹对得上
  ④**canary 数据**：埋一个只可能来自真实链路的标记值（如 `9999`），它出现在响应体里就说明走的是 mock
- `source` = 用例从哪来，**五类前缀**：`AC:REQ-x.y` ｜ `发现:tc-NNN#F-xx` ｜ `反馈:<卡/轮次>`（**须带锚点**，只写「用户反馈」会被报 WARN）｜ `探索:<本轮探的问题>` ｜ `回归:<原 CAS-NNN>`（v5.28.0：哨兵复挂后修复卡 `source: 回归:CAS-NNN`，修好后**复用原 CAS 行**回填 pass，不新造行；`source` 前缀 ∈ 发现/反馈/回归/探索且非 retired 的行 = **基线哨兵集**，交付/上线轮收口必须全 `pass`）
- `last` = `pass` ｜ `fail` ｜ `skip` ｜ `unknown` ｜ `retired`
  （**`unknown` = 未回填**，不许写成 `pass`；`retired` = 已作废但保留行）
- **字段内不许出现 `|`**（列分隔符）；要写多个用 `,` 或 `/`

## 4. 每轮更新的顺序

1. 跑基线用例 → 回填 `last`；**哨兵 `last=fail` = 二进宫**：建修复卡 `source: 回归:CAS-NNN`（当轮最高优先级），不许顺手改掉不记
2. 读本轮**发现项**（`测试卡/tc-NNN/发现项.md`）与**用户反馈** → 新增 `CAS-NNN`，`source` 写清锚点；**每个修复卡配一条哨兵**并把 CAS 号填进卡 `reg_case`
3. `python scripts/case_audit.py <项目根>` → **0 ERROR** 才算登记完成
4. `python scripts/case_audit.py <项目根> --hotspots` → 看哪条链路/哪个文件**反复出问题**（热区）
5. `python -X utf8 scripts/regression_audit.py <项目根>` → 哨兵线/基线线/二进宫处置/极速债**四条线 0 ERROR** 才算防线收口；本轮改动涉及的文件跑 `--impact <路径>`，把碰撞哨兵集纳入 targeted
6. 本轮新增的复杂用例若被证明有效，按 `记忆/角色/测试工程师.md` 的升格规则沉淀

## 5. 与其它文件的分工（别互相替代）

- `代码/测试/用例库.md`（本文件）：**跨卡、跨轮的用例资产**——判据、数据、反 mock、最近结果
- `测试卡/tc-NNN/覆盖矩阵.md`：**本轮**维度覆盖与证据指针
- `代码/测试/开发说明.md`：本轮测试范围、结论、Bug 登记
- `进度/测试工程师.json`：角色状态与开口
- **老工程已有 `代码/测试/操作清单.md`**：就地保留，**新内容只写用例库**，不要把两边抄成两份

## 6. 变更后一致性用例怎么写（v5.24.0，覆盖维度 ⑫）

> 形态固定四段：**`给出去 → 做动作 → 收回来 → 问产物对不对`**。
> 例：把 A 绑上高级管理员角色 → A 生成一张审批单 → 取消 A 的高级管理员角色 → **问 A 还能不能看到这张单**。
> 它和 ⑤（静态角色矩阵"这个角色能不能进"）、⑥（同一实体状态机"这个实体自己转态对不对"）**不是一回事**——它查的是**回收之后原来产出的东西该不该还看得见**，是两者的夹角。

**四个字段各怎么写（不改 schema，不加第 10 种方法名）**

| 列 | 这类用例怎么写 |
|---|---|
| `method` | **`状态迁移+场景法`**（组合写法，**九个合法名字已足够**；不要造 `变更后一致性` 这种第 10 个名字——检查器的合法方法表是固定的，写别的会被报「未知方法」，而收益只是名字更准） |
| `data` | **强制三段式**：`前置态 / 变更动作 / 断言集`，且必须可复跑。例：`前置：A=高级管理员，单据 S 归属 A；变更：撤销 A 的角色；断言：七面逐面拒绝态` |
| `anti_mock` | **四通道同时断言**（少一条都可能假通过）：①A 账号界面重走原路 ②换 B 账号登录 ③直调接口须被拒 ④直查库/索引确认归属与派生数据真的变了。**只测界面必漏缓存层与搜索索引层** |
| `source` | 指向 PRD 的「变更语义」条款：`AC:REQ-x.y`（**判据不在契约里就不许写这条用例**——先要求产品经理补三问，补不上提 CR，别自己编期望值） |
| `scope` | 通常 `tc-NNN`（出自哪张测试卡）；跨轮复用的写 `global` |
| `last` | 同常规。**`unknown` 不许写成 `pass`** |

**七面是断言的对象**：列表 / 详情 / 直达链接 / 导出 / 搜索 / 通知 / 统计。一条用例可以只打其中几面，但**同一对象 × 同一变更事件的面集合要在测试卡 `变更矩阵.md` 里对齐**（`machine:mutation` 七列），检查器 `python -X utf8 scripts/mutation_coverage_audit.py <项目根>` 会核「声明与自相矛盾」。

**降维（不是偷工）**：`给出去 → 做动作` 这一段已被 AC 的普通功能用例覆盖，**这类用例只测"收回来之后"**；架构师已给出同源证据的多个面可合并成一类。
